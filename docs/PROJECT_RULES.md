# YS Fourcut — 상세 제품·구현 규칙

## 목표

웹캠으로 사진 네 장을 촬영하고 세로 네컷 스트립으로 합성하여, 사용자가 보유한 **AHAPOS 영수증 프린터**로 출력하는 로컬 포토부스를 만든다. 프로젝트 가칭은 `YS Fourcut`이다. 브랜드는 사용자 확인 사항이며 정확한 모델·연결 방식·운영 OS는 아직 미확인이다.

핵심은 **촬영 경험, 감열지에서 알아볼 수 있는 사진, 안정적인 실제 인쇄**다. 일반 사진 프린터용 컬러 출력이나 화면 시안만 완성하고 끝내지 않는다. 인생네컷의 사용 흐름을 참고하되 로고·캐릭터·브랜드 자산은 복제하지 않는다.

**현재 우선 납품 범위는 프린터 없는 가상 출력 버전이다.** 사용자가 아직 프린터를 준비하지 못했으므로, 동일한 웹 → .NET API 호출로 .NET이 실제 용지 모양의 영수증 이미지를 렌더링하는 프로그램부터 완성한다. 실물 연동은 후속 단계이며 가상 버전 완료를 막지 않는다.

## 읽는 방법

전체 자동 로딩용이 아니다. 경로는 프로젝트 루트 기준이며 현재 tasks/NN.md가 지정한 절만 읽는다. 한 세션의 실행 범위와 종료 규칙은 루트 AGENTS.md가 정한다. 상세 요구를 보존한 참고 문서이며 다른 단계 구현을 시작하라는 뜻이 아니다.

## 기본 구현 방향

- 기존 앱이 있다면 그 스택과 패키지 매니저를 유지한다.
- 앱이 없다면 React + TypeScript + Vite 웹앱과 C#/.NET 10 로컬 호스트를 만든다. 웹앱은 촬영·합성, 호스트는 화면 파일 제공·작업 검증·가상 영수증 렌더링과 후속 Windows 인쇄를 맡는다.
- 개발 도구 버전은 구현 당시 공식 요구사항과 호환되는 안정 버전을 선택하고 lockfile에 고정한다. 패키지 매니저는 하나만 사용한다.
- 운영 대상은 우선 Windows 11 + Chrome/Edge인 한 대의 PC로 가정한다. 실제 운영 환경과 프린터 지원을 확인하고, 다른 OS라면 가정을 수정한다.
- 현재 개발은 `/home/msilot/ysfourcut`에서 Linux용 Node/.NET으로 진행한다. **Vite와 .NET 가상 호스트는 WSL, 실제 화면과 웹캠은 Windows Chrome/Edge**를 사용한다. 웹캠 USB를 WSL에 전달할 필요가 없다.
- Linux 호스트는 `net10.0`과 Skia로 구성한다. Windows 전용 TFM/UI/System.Drawing/GDI를 가상 실행의 필수 의존성으로 넣지 않는다. 플랫폼별 worker 실행 경로와 설정/기록 저장 경로도 분리한다.
- 개발 브라우저는 `http://127.0.0.1:5173`, Vite의 `/api` 프록시는 WSL의 `127.0.0.1:4317`로 고정한다. 개발 Origin만 정확히 허용하고 인증·쿠키·이미지 API 검사를 유지한다. 프록시를 Windows 호스트 주소로 바꾸는 구조는 기본으로 쓰지 않는다.
- 현재 Fedora 42와 Node 25, Linux .NET 미확인 상태는 WSL 가이드에 기록되어 있다. 프로젝트의 Node 24 LTS/지원되는 .NET 10 환경을 준비하되 배포판 업그레이드, 전역 도구 변경, 방화벽 변경을 자동 수행하지 않는다.
- 운영 시 로컬 호스트가 `http://127.0.0.1:4317`에서 웹앱과 API를 함께 제공한다. 클라우드 서버·외부 사진 DB·Docker를 추가하지 않는다.
- 기본 실행은 `--printer-mode virtual`이다. .NET에서 `content.png`, `paper.png`, `appearance.png`를 생성하고 웹은 인증된 API로 받아 표시한다. OS 프린터 큐/드라이버 없이 동작해야 한다.
- 기존 `CrossEscPos.Rendering.Skia`와 `CrossEscPos.Abstractions` 1.2.0을 우선 재사용한다. 정확한 dot 배치와 용지 외관만 얇게 구현하고 에뮬레이터 전체를 새로 만들지 않는다. 패키지 복원·대상 OS 네이티브 런타임·PNG 생성은 실제로 검증한다.
- 현재 가상 출력에는 ESC/POS 인코딩이나 `CrossEscPos.Core`를 넣지 않는다. Core의 원시 데이터 로그 위험과 자동 여백/배율 처리는 별도 문서에 기록되어 있다. 상용 프로그램 설치·구매는 기본 경로에 넣지 않는다.
- 후속 실물 인쇄의 우선 후보는 **Windows에 등록된 AHAPOS 큐에 GDI 비트맵 출력**이다. 작은 패턴으로 용지 길이·출력 폭·드라이버의 이미지 지원부터 확인한다.
- 실물 출력 호스트/작업 프로세스는 Windows에서 실행한다. 가상 호스트는 WSL에서도 Skia 네이티브 의존성을 확인해 검증할 수 있다. Windows 프린터가 WSL에 자동으로 보인다고 가정하지 않는다.
- 후속 Windows 배포는 WSL에서 `win-x64` publish 후 Windows에서 실행·검수한다. Linux 테스트 통과나 publish 성공을 Windows 실행/프린터 검증으로 보고하지 않는다.
- 기존 코드나 실물 검증이 다른 방식을 요구할 때만 어댑터를 교체한다. WebUSB·Web Serial·RAW ESC/POS를 전부 선제 구현하지 않는다.
- `window.print()`를 기본 흐름으로 쓰지 않는다. 드라이버 설치·교체, 보안 권한 우회, 전체 프린터 큐 삭제를 자동 실행하지 않는다.

## MVP 범위

1. 카메라 미리보기, 장치 선택, 카메라 권한 오류 안내.
2. 기본 3초 카운트다운으로 네 장 자동 촬영. 현재 컷과 남은 컷 표시.
3. 촬영 취소·전체 다시 찍기·선택한 한 컷 다시 찍기.
4. 세로 1열 × 4컷 합성, 기본 프레임 2종, 짧은 하단 문구와 날짜.
5. 실제 전송할 흑백 비트맵 미리보기, 밝기·대비 조정.
6. 프린터 연결·테스트 출력·한 장 인쇄·실패 안내·사용자 선택 재인쇄.
7. 합성 PNG 저장, .NET이 만드는 가상 영수증·치수 표시·오류 시뮬레이션, 다음 사용자용 세션 초기화.

현재 버전은 6번의 실제 장치 연결 대신 가상 프로필 선택과 가상 테스트 출력을 제공한다. 실제 장치 코드가 미구현이면 기능을 숨기거나 비활성화하고 명시한다.

회원가입, 결제, 클라우드 갤러리, QR 다운로드 서버, AI 보정, 다중 프린터 관리는 MVP에 넣지 않는다. 사진 선택용 8장 촬영과 2열 편집도 후속 기능이다.

## 구조와 경계

- 촬영, 합성, 흑백 변환, 프린터 프로토콜, 장치 전송, 화면 상태를 별도 모듈로 나눈다.
- Canvas에서 인쇄 원본을 직접 만든다. DOM 스크린샷을 인쇄 원본으로 사용하지 않는다.
- 레이아웃 계산·명암 변환·디더링·바이트 인코딩은 입출력이 명확한 순수 함수로 만든다.
- 웹앱은 최종 1비트 비트맵과 프로필 revision을 같은 `POST /api/print-jobs`로 보낸다. 호스트의 `IPrinterBackend` 뒤에 `VirtualReceiptPrinter`와 후속 실물 어댑터를 둔다. `MockPrinter`는 단위 테스트 전용이다. UI에 OS/프린터 명령을 노출하지 않는다.
- 모드는 서버 설정으로 결정하고 요청 본문으로 강제 변경하지 못하게 한다. 가상/실물 사이 자동 전환·실패 후 자동 재출력은 금지한다.
- `ReceiptLayout`의 정수 dot 좌표를 공통 계약으로 둔다. 가상 렌더러는 최종 비트맵을 다시 디더링·축소하지 않는다. 종이 질감·그림자·절취 효과는 외관 이미지에만 적용하고 인쇄 원본에는 넣지 않는다.
- `PrinterProfile`에는 큐 식별, 드라이버, 용지 폭(mm), 인쇄 가능 폭(dot), X/Y 해상도, 여백, 최대 길이, 검증된 페이지/이송/커팅 설정을 둔다. RAW 통신 설정·이미지 명령은 그 어댑터를 구현할 때만 추가한다.
- 58/80mm라는 용지 폭만으로 384/576dot를 확정하지 않는다. 개발용 예시 값에는 미검증 표시를 붙인다.
- 검증되지 않은 실제 프린터 프로필로 방문자용 인쇄를 활성화하지 않는다. 운영자 테스트를 통해 프로필을 확인한다.
- `kind=virtual` 프로필은 스키마/범위 검증만으로 사용할 수 있다. `kind=hardware`의 실물 검수와 분리하고 AHAPOS 검증 완료로 표시하지 않는다. 가상 80/58mm 프리셋 수치는 특정 AHAPOS 사양이 아니다.
- 큐·드라이버·폭·DPI·인쇄 관련 설정 변경 시 프로필 검증을 해제한다. 큐가 사라졌다고 다른 기본 프린터로 대체하지 않는다.
- React 렌더링이나 effect 재실행 때문에 촬영·인쇄가 중복되지 않게 한다.

## 촬영과 사진 처리

- 영상 프레임이 준비된 뒤 촬영한다. 준비되지 않은 검은 프레임은 사진으로 확정하지 않는다.
- 미리보기의 좌우 반전, 캡처 반전, 최종 결과를 일치시킨다. 반전 옵션이 글자와 프레임까지 뒤집지 않게 한다.
- 화면 미리보기와 저장되는 사진의 크롭 영역을 맞춘다. 비율을 강제로 늘리지 않는다.
- 원본은 세션 메모리에 보관하여 밝기 변경·재합성·재인쇄에 재사용한다. 재촬영은 지정한 슬롯만 교체한다.
- 촬영 취소·초기화 시 타이머를 정리한다. 이전 세션의 비동기 결과가 새 세션에 들어오지 않게 한다.
- 카메라 장치 변경·화면 종료 시 불필요한 MediaStream track을 중지한다. 대기 화면에서도 계속 쓸 때만 유지한다.

## 감열지용 이미지와 인쇄

- 흰 배경에 사진 네 장과 여백을 배치한다. 넓은 검정 배경은 기본 프레임에서 피한다.
- 사진을 실제 인쇄 dot 크기로 조정한 뒤 명암 조정·그레이스케일·1비트 디더링을 적용한다. 사진 원본에는 파괴적 변환을 하지 않는다.
- 사진 영역은 Floyd–Steinberg 등을 비교할 수 있게 하고, 글자·프레임은 선명한 흑백으로 합성한다. 알고리즘 선택은 실물 결과로 조정한다.
- 한국어와 날짜는 폰트 로딩 완료 후 Canvas에 그려 출력 원본에 포함한다. 프린터의 한글 코드페이지 지원을 전제로 삼지 않는다.
- 인쇄 미리보기와 인코더는 같은 최종 비트맵을 사용한다. 화면의 모양과 종이의 배치가 별도 코드로 어긋나지 않게 한다.
- 후속 GDI 경로는 한 네컷을 한 페이지·한 작업·한 부로 만든다. 용지 길이·DPI·인쇄 영역을 시작 전에 검사하고 자동 축소/확대하지 않는다.
- 최종 비트맵의 byte 행 길이와 GDI DIB의 DWORD 행 정렬을 구분한다. 팔레트·비트 순서·상하 방향·흰 패딩을 작은 고정 패턴으로 검증한다.
- GDI 드라이버가 픽셀을 다시 처리할 수 있으므로 실제 프린터 명령 바이트까지 미리보기와 같다고 주장하지 않는다. 원본은 같게 유지하고 실물 품질을 검수한다.
- 실물 GDI 경로의 이송/커팅은 검증된 드라이버 설정으로 처리한다. 같은 작업 뒤에 별도 커팅 명령을 덧붙이지 않는다.
- ESC/POS 대체 경로를 구현한다면 모델의 지원 이미지 명령·분할·이송·커팅을 확인한다. PNG를 RAW로 그대로 보내거나 `GS v 0`를 보편 명령으로 가정하지 않는다.
- 작은 테스트 패턴부터 확인한다. 전송 크기·속도·사진 농도·긴 이미지의 안정성을 확인한 뒤 네컷을 출력한다.

## 출력 상태와 실패 처리

- 동시에 인쇄 작업 하나만 허용한다. 연결·해제·프로필 변경·새 세션 시작도 전송 중에는 충돌하지 않게 막는다.
- 서버에서 작업 UUID와 내용 digest로 중복 접수를 막는다. 같은 ID/같은 내용은 기존 작업을 반환하고, 같은 ID/다른 내용은 충돌 오류로 처리한다.
- 작업 메타데이터는 사진 없이 로컬 기록에 원자적으로 남긴다. 재시작·응답 유실 시 기존 작업을 조회하고 자동 재인쇄하지 않는다.
- 인쇄 버튼 연타, 느린 전송, 장치 분리, 부분 전송 실패를 처리한다. 전송에 timeout과 복구 경로를 둔다.
- OS 인쇄는 별도 작업 프로세스에서 수행한다. timeout이 OS 작업 취소를 의미하지 않으며, 이후 결과는 불명확 상태로 두고 큐/종이를 확인한다.
- 일부 데이터가 전송된 뒤 실패하면 자동으로 처음부터 재전송하지 않는다. 종이 상태를 확인하고 사용자가 재인쇄를 선택하게 한다.
- GDI 제출 성공은 `프린터 큐에 전달했어요. 종이를 확인해 주세요`로 표시한다. 큐에서 작업이 사라진 것도 물리적 배출 완료로 단정하지 않는다.
- OS 큐에 해당 작업이 남아 있거나 출력 결과가 불명확하면 새 인쇄·세션 초기화를 막는다. 실패한 작업을 다른 어댑터로 자동 재시도하지 않는다.
- 용지 없음·덮개 열림 등은 실제 상태 응답이 있을 때만 확정적으로 표시한다. 그 외에는 가능한 확인 항목으로 안내한다.
- 가상 모드는 화면에 지속적으로 표시하고 완료 문구는 `가상 영수증을 만들었어요`로 한다. `rendered`는 서버 이미지 생성 완료이며 실물 출력 성공이 아니다. 실패는 `virtual_failed`이고 OS 큐/용지 확인 없이 정리할 수 있다.
- 가상 오류 주입은 지연·용지 없음·덮개 열림·중간 렌더 실패 등을 명시적으로 표시한다. 실제 프린터 상태를 읽었다고 표현하지 않는다. .NET이 꺼지면 가상 출력도 실패해야 한다.

## 개인정보와 운영

- 원본 네 장은 브라우저 메모리 안에서만 처리하고, 최종 1비트 이미지만 같은 PC의 로컬 호스트/작업 프로세스에 전달한다. 외부 서버·분석·오류 수집 서비스로 보내지 않는다.
- 앱은 이미지 파일을 자동 저장하지 않으나 Windows 스풀러/드라이버의 임시 디스크 저장은 가능하다. 시스템 전체에서 사진이 디스크에 절대 남지 않는다고 보장하지 않는다.
- 가상 PNG 결과만 서버 메모리에 임시 보관한다. 생성 후 절대 TTL 10분, 인증 세션당 완료 작업 최대 3개/64MiB, 작업당 PNG 합계 32MiB를 적용한다. 다음 촬영에서 서버 결과도 지우고 만료 후 `410`을 반환한다. 원시 픽셀 버퍼는 인코딩 후 해제한다.
- 결과 이미지는 세션 인증·요청 헤더를 포함한 fetch로 가져와 Blob URL로 표시한다. 공개 정적 경로, 로그, 브라우저/HTTP 캐시에 남기지 않는다. 렌더링 모듈이 사진 데이터를 로그에 쓰지 않는지도 확인한다.
- PNG는 사용자가 저장을 선택할 때만 다운로드한다. 사진을 localStorage나 IndexedDB에 자동 보관하지 않는다.
- `다음 촬영` 또는 유휴 만료 시 사진, 합성 이미지, Object URL, 관련 상태를 정리한다. 전송 중·큐 작업 잔여·결과 불명확 상태에서는 자동 초기화하지 않는다.
- 가상 서버 결과 삭제가 실패하면 화면 사진부터 지우되, 서버 정리 성공 또는 재시작 후 빈 캐시 확인 전에는 다음 사용자 세션을 시작하지 않는다.
- 장치·프레임 같은 비민감 설정만 저장할 수 있다. 사진 데이터와 인물 정보는 로그에서 제외한다.
- 로컬 호스트에는 루프백 바인딩, Host/Origin 검사, 실행기 일회용 코드와 세션 인증, 요청 크기 제한을 적용한다. 클라이언트가 임의 프린터 명령·경로를 지정하지 못하게 한다.

## 검증과 완료 보고

- 구현 시 `dev`, `build`, `lint`, `typecheck`, `test`의 실제 실행 명령을 `README.md`에 기록한다.
- 레이아웃 크기, 1비트 복원 픽셀 일치, paper 이미지의 본문 crop 일치, 치수/용지 길이, 중복 접수, 실패·응답 유실·재시작·결과 만료를 의미 있는 테스트로 검증한다. DIB/ESC/POS 테스트는 해당 실물 경로를 구현할 때 추가한다.
- 실제 .NET을 띄워 촬영 → 합성 → HTTP 접수 → 서버 PNG 표시 → 초기화를 끝까지 확인한다. 이 검수에서 API stub이나 프런트 전용 Canvas로 서버를 대체하지 않는다. 권한 거부·연결 실패와 가상 모드의 OS 인쇄 미호출도 확인한다.
- 실물 검수에는 프린터 모델, OS, 브라우저, 프로필, 출력 폭, 농도, 네 컷 누락 여부, 이송·절취, 반복 출력 결과를 남긴다.
- `.NET 가상 출력 검증`, `실제 장치로 전송 확인`, `종이 결과 확인`을 별개로 보고한다. 가상 검증은 AHAPOS 드라이버·명령·농도·커터의 검증이 아니다.
- 실물 테스트가 불가능하면 소프트웨어 작업은 마무리하되 하드웨어 인쇄는 미검증으로 남긴다. 남은 확인 항목과 재현 절차를 제공한다.
- 실행하지 않은 테스트를 통과했다고 쓰거나, 미구현 어댑터를 실제 작동한다고 쓰지 않는다.
