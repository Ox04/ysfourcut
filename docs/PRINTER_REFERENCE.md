# AHAPOS 프린터 확인 기록

갱신일: 2026-08-31. 이 파일은 확인 기록이며, 프린터 호환성 인증이나 구현 완료 보고서가 아니다.

## 확인된 사실

- 사용자가 보유한 프린터의 브랜드는 **AHAPOS**라고 알려 주었다.
- 사용자는 현재 영수증 프린터가 준비되지 않았으며, 동일한 웹 → .NET 호출로 현실적인 영수증 이미지를 만드는 가상 출력 프로그램부터 설계해 달라고 요청했다.
- 개발 환경은 사용자 확인 **WSL**이다. 현재 배포판은 Fedora Linux 42/x64로 확인했고 Windows → WSL 루프백 HTTP 접속을 임시 서버로 확인했다. .NET SDK/앱 실행은 아직 미확인이다. 상세 준비 상태는 `../WSL_DEVELOPMENT.md`를 참고한다.
- 같은 프린터를 사용했던 코드로 다음 파일을 제공했다: [astraea의 page.tsx](https://github.com/msilot1001/astraea/blob/2a98e42bb1e0f68c704d72632a3ed2e9d7a384e4/app/admin/otp/page.tsx).
- 위 파일의 정상화 URL과 raw URL은 이전 확인에서 404였으며, 소스 내용은 아직 읽지 못했다.
- 현재 개발 PC의 Windows 등록 프린터 목록에서 AHAPOS로 식별되는 큐를 찾지 못했다. 다른 운영 PC에 설치돼 있거나 다른 이름일 수 있으므로 프린터가 없다고 단정하지 않는다.
- 시원아이티 자료실 검색 결과에서 `AHAPOS Printer Driver`와 `AHAPOSPrinterDriver.exe`라는 자료가 확인되었다. 상세 페이지 열기는 실패했고 파일을 다운로드/실행하지 않았다. 모델별 지원, 제작사, 파일 서명, 안전성은 검증하지 않았다. [자료실 항목](https://m.c1it.co.kr/myboard/st_myboard/229923)

| 항목 | 상태 |

| 운영 PC의 OS/브라우저 | 미확인. Windows 11 + Chrome/Edge를 설계 기본 가정으로 사용 |

| 감열 방식·용지 폭·인쇄 가능 dot 폭·DPI | 미확인. 흑백 영수증 사진을 설계 대상으로 함 |

| 자동 커터·드라이버 이송 동작 | 미확인 |

## 이번 설계에서 선택한 것

현재는 `VIRTUAL_PRINTER_DESIGN.md`를 기준으로 **브라우저 촬영/합성 → .NET 로컬 API → 기존 Skia 렌더링 모듈을 이용한 가상 영수증 PNG → 웹 표시**를 먼저 구현한다. OS 프린터나 드라이버 설치가 필요 없는 버전이다. 문서 작성 단계이며 프로그램 구현·실행 검증은 아직 하지 않았다.

가상 80/58mm 프리셋은 일반적인 예시 설정일 뿐 사용자의 AHAPOS 모델 사양이 아니다. 가상 출력 성공으로 하드웨어 검증을 완료 처리하지 않는다.

후속 실물 연결은 `SERVICE_DESIGN.md`의 **동일한 .NET API → AHAPOS 등록 큐의 GDI 이미지 출력**을 우선 후보로 한다. 이는 앱의 설계 결정이며 해당 AHAPOS 모델의 지원이 확인된 사실은 아니다.

기존 코드가 확보되면 그 안의 프린터 관련 import/API까지 추적한다. 확인된 연결 방식이 더 적합하면 화면과 최종 비트맵 계약은 유지하고 인쇄 어댑터만 바꾼다. 실제 작업 실패 후 다른 어댑터로 자동 재출력하지 않는다.

## 실제 장치를 확인할 때 채울 기록

1. 본체 모델명, 프린터 큐 이름, 드라이버명/버전, 포트 종류.
2. 운영 PC의 OS와 브라우저, Windows 테스트 페이지 결과.
3. 드라이버에서 읽은 DPI/인쇄 영역, 실제 작은 패턴의 폭과 방향.
4. 긴 용지 설정, 한글과 사진 품질, 이송/절취, 연속 출력 결과.
5. 기존 코드에서 재사용한 파일·함수와 수정 이유.

브랜드와 큐 등록 정보만으로 검증 프로필을 활성화하지 않는다. 프로필 검증은 작은 패턴과 네컷 샘플의 **실제 종이 결과**를 확인한 뒤 기록한다.
