# 영수증 외관 (04번에서 구현)

작성일: 2026-08-31. `appearance.png`를 만드는 실제 파라미터만 적는다.
구현: `apps/print-host/Rendering/ReceiptAppearanceRenderer.cs`. 07/12번 디자인 작업이 이 문서를 이어 쓴다.

**실물 대조는 하지 않았다.** 여기 값은 감열 영수증처럼 보이게 만든 외형이며 AHAPOS의 실제 농도·피드·용지 반응과
같다고 주장하지 않는다.

## 세 이미지의 역할

| 이미지 | 내용 | 04번이 바꾸는가 |
| --- | --- | --- |
| `content.png` | 요청한 1비트를 그대로 복원한 흑백 | 아니오. 픽셀 동일 |
| `paper.png` | 순백 용지 + 좌우 여백 + 앞뒤 이송 | 아니오. 픽셀 동일 |
| `appearance.png` | 종이색·질감·두께·바닥 그림자·절취 외형 | 04번이 새로 만든다 |

외관은 **별도 캔버스**에서만 그린다. 원본 지면을 `Multiply`로 올리므로 검정 dot는 검정 그대로 남고
흰 여백만 종이색이 된다. 배경/그림자/절취가 내용 픽셀을 바꾸지 않는다.

## 캔버스와 원점

| 항목 | 값 |
| --- | --- |
| 배율 | 1:1 (1 dot = 1 px). 확대해 그리지 않는다 |
| 바깥 여백 | 사방 24px (`OuterMarginPx`) |
| 캔버스 크기 | `(paperWidthDots + 48) × (paperHeightDots + 48)` |
| 종이 원점 | `(24, 24)` |
| 내용 원점 | `(24 + contentXDots, 24 + contentYDots)` = 80mm 기본에서 `(56, 48)` |
| 배경 | **투명**. 바닥 표면은 웹(07/12)이 정한다 |

바깥 여백과 그림자는 **물리 mm에 포함되지 않는다**. 80mm 프리셋의 576×1788 내용은 지면 640×1876dot,
80×234.5mm 그대로이고 appearance 캔버스만 688×1924px이다.

## 색과 효과 파라미터

| 항목 | 값 | 메모 |
| --- | --- | --- |
| 종이색 | `#FAF7F1` (250,247,241) | 밝은 아이보리. 검정 대비 유지 |
| 종이 가장자리 | `#DFD8CB` (223,216,203), 1px stroke | 종이 두께감 |
| 바닥 그림자 | `#3C342C`, alpha 70, blur σ=7, y+6px | 부드럽게 한 방향 |
| 섬유 질감 | 밝기를 최대 3단계만 낮춤 (세로로 늘인 잡음 + 세로 결) | 실제 출력 색 4종만 나온다 |
| 잉크 | 원본 그대로 검정 | 색을 바꾸지 않는다 |

질감은 아주 약하다. 실제 측정 결과 종이 여백에는 `(250,247,241)`~`(247,244,238)` 네 단계만 나타나며
검정 dot는 `(0,0,0)` 그대로다. 모든 흰 여백을 누렇게 덮어 대비를 떨어뜨리지 않는다.

## 절취 외형

| `cutStyle` | 외형 |
| --- | --- |
| `straight` (기본) | 위아래 수평 절단 |
| `tear` | 이송 여백 안에서만 흔들리는 불규칙 절취면 |
| `none` | 미절취 롤. 종이가 캔버스 위아래 끝까지 이어진다 |

`tear`의 요철 깊이는 `min(6dot, 이송 여백 / 3)`이라 80mm 기본에서 위 6dot(앞 이송 24dot 안),
아래 6dot(뒤 이송 64dot 안)이다. **사진과 문구에는 절대 닿지 않는다.**
굵은 흔들림과 잔결을 섞은 불규칙선이며 규칙적인 톱니를 쓰지 않는다.

## 추정 효과 (기본 꺼짐)

| 이름 | 내용 |
| --- | --- |
| `ink_bleed` | 잉크가 아주 약간 번진 느낌 (blur 0.7, alpha 90) |
| `banding` | 감열 헤드의 옅은 가로 밴딩 (3px 간격, 최대 18단계) |

기본값은 **빈 목록(둘 다 꺼짐)**이다. `content.png`/`paper.png`에는 어떤 경우에도 적용하지 않는다.
알 수 없는 효과 이름은 거부한다. 이 두 효과는 실측이 아닌 **추정**이며, 실제 장치 특성과 같다고 표시하지 않는다.

## seed와 revision

- `appearanceRevision = "a1"`. 외형 알고리즘이 바뀌면 이 값을 올린다.
- 질감·절취선은 `seed`에만 의존하는 해시 난수로 만든다. 같은 `seed`·revision·입력이면 **같은 픽셀**이 나온다.
- 작업에 seed와 revision을 함께 기록하면 같은 작업을 다시 조회해도 질감/절취선이 바뀌지 않는다(05번).

## 크기 한도

`ReceiptRenderer`가 **그리기 전에** `Measure()`로 캔버스 크기를 받아 이미지당 8,000,000픽셀 한도를 확인하고,
그린 뒤에는 PNG 헤더로 실제 크기를 다시 확인한다. 작업당 인코딩 합계 32MiB 한도도 그대로다.
초과는 `RENDER_LIMIT_EXCEEDED`이며 잘라내기나 자동 축소로 숨기지 않는다.

## 검수 이미지 만드는 법

인공 패턴 산출물이며 저장소에 커밋하지 않는다(`.gitignore`의 `*.png`). 필요할 때 다시 만든다.

```bash
YSFOURCUT_RENDER_INSPECT_DIR=/tmp/ysfourcut-inspect \
  npm run test:host -- --filter FullyQualifiedName~RenderInspectionTool
```

만들어지는 조합: `80-straight`, `80-tear`, `80-none`, `58-straight`, `80-short`, `80-long`, `80-effects`.
각각 `-content.png`, `-paper.png`, `-appearance.png`가 생긴다.

04번에서는 이 조합을 실제로 열어 확인했다: 80/58mm, 짧은 내용(120dot)과 긴 스트립(1788dot),
절취 세 방식, 정확 보기(`paper`)와 외관 보기(`appearance`)의 1:1 확대 비교.
실제 인물 사진은 사용하지 않았고 외부 서비스에 올리지도 않았다.
