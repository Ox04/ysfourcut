# 90 — AHAPOS 장치와 기존 코드 조사

- 권장 모델: **Opus 5 / medium**
- 입력: `90 진행해`
- OMC 입력: `/ys-task 90` — 프린터 준비 후에만 사용한다.
- 실행 시점: 사용자가 실제 프린터를 준비한 뒤 이 번호를 요청했을 때만.
- 목표: 91에서 쓸 실제 연결 방식/모델/프로필 근거 확보.

## 이번에 읽을 것

- 진행표, Windows 실행 관련 13 handoff, `docs/PRINTER_REFERENCE.md`.
- `docs/PROJECT_RULES.md`의 기존 프린터 코드 절.
- `SERVICE_DESIGN.md`의 6~7절과 `WSL_DEVELOPMENT.md`의 6절.

## 할 일

1. 기존 astraea 커밋의 page.tsx와 필요한 프린터 import/API를 권한 있는 경로로 확인한다. 기존 404 기록을 보존하고 접근 우회/인증정보 수집을 하지 않는다.
2. Windows의 실제 큐/드라이버/포트와 본체 모델, 용지 폭/dot/DPI/이송/커터를 확인한다. 브랜드나 다른 모델 정보를 대입하지 않는다.
3. 기존 코드는 텍스트만 인쇄했는지 이미지도 보냈는지 구분한다. OTP/인증 업무 코드와 비밀값은 가져오지 않는다.
4. GDI 후보가 맞는지, 기존 확인된 RAW/COM/SDK가 필요한지 근거로 결정한다. 여러 어댑터를 미리 만들지 않는다.
5. 장치가 없거나 정보가 부족하면 확인 가능한 소프트웨어 조사를 마치고 남은 정확한 조건만 기록한다. 사양을 지어내어 hardwareVerified를 켜지 않는다.

## Acceptance Criteria — 완료 확인

[공통 완료 기준](DEFINITION_OF_DONE.md)을 적용한다. 변경 범위는 장치·기존 코드 조사 기록이며 실제 드라이버/출력 설정은 바꾸지 않는다.

| ID | 통과 조건·검증 |
| --- | --- |
| AC-90-01 | 본체 모델/Windows 큐·드라이버·포트/용지·dot·DPI·커터의 확인값과 출처를 기록한다. 브랜드만으로 다른 모델 사양을 대입하지 않는다. |
| AC-90-02 | 권한 있는 기존 astraea 코드의 텍스트/이미지 출력 경로를 구분하거나 접근 불가 근거를 남긴다. OTP·비밀값은 복사하지 않는다. |
| AC-90-03 | 증거에 따라 91에서 구현할 어댑터 하나와 검수할 프로필 항목을 정한다. 결정 근거가 부족하면 미확인 항목과 재개 조건을 명시하고 partial로 남긴다. |

## 이번에 하지 않을 것

드라이버 자동 설치/교체, GDI 어댑터 구현, 전면 검정·장시간 출력, 전체 큐 삭제. 90 handoff 뒤 멈춘다.
