# 13 — Windows 배포 폴더

- 권장 모델: **Sonnet 5 / medium**
- 입력: `13 진행해`
- OMC 입력: `/ys-task 13`
- 선행 작업: 11, 12. 12가 사용량 때문에 보류면 기능 검수된 11 결과의 임시 빌드임을 표시한다.
- 목표: 정해진 구조 그대로 Windows에서 실행할 수 있는 가상 버전 패키지.

## 이번에 읽을 것

- 진행표, 01/11/12 handoff의 실행/변경 항목, 실제 프로젝트/스크립트/패키지 설정.
- `WSL_DEVELOPMENT.md`의 6절, `SERVICE_DESIGN.md`의 11절.
- `VIRTUAL_PRINTER_DESIGN.md`의 2절 중 패키지·라이선스만.

## 할 일

1. `npm run package:win`이 웹 빌드와 .NET win-x64 self-contained publish를 묶게 한다. 실제 프로젝트 경로를 쓰고 Native AOT/ReadyToRun은 처음부터 추가하지 않는다.
2. wwwroot에 웹 자산·로컬 폰트가 포함되고 Windows용 Skia 네이티브 파일이 들어오는지 확인한다. Linux RID 파일만 있는 패키지를 Windows 완료로 처리하지 않는다.
3. 배포 결과는 `dist/win-x64` 같은 명시적 작업 경로로 제한한다. Windows 실행 시험은 로컬 경로의 복사본에서 하며 사용자 프로젝트/다른 배포 폴더를 덮어쓰거나 광범위하게 삭제하지 않는다.
4. 가능하면 Windows에서 virtual 기본 실행, 브라우저 bootstrap, 인공 샘플 PNG 생성, 인터넷 없이 로컬 자산 로드를 확인한다. WSL의 같은 앱 4317과 충돌하면 해당 앱 프로세스만 정리한다.
5. 운영 PC에 Node/.NET SDK/프린터 드라이버 없이 가상 출력 가능한지 점검한다. 배포판·방화벽·드라이버를 설치/변경해 맞추지 않는다.
6. 실제 포함한 패키지/폰트의 THIRD_PARTY_NOTICES와 실행 안내를 갱신한다.

## Acceptance Criteria — 완료 확인

[공통 완료 기준](DEFINITION_OF_DONE.md)을 적용한다. 변경 범위는 패키징 스크립트·배포 설정·라이선스/실행 안내다.

| ID | 통과 조건·검증 |
| --- | --- |
| AC-13-01 | 실제 `npm run package:win`이 웹 빌드와 win-x64 self-contained publish를 수행하고 명시된 출력 폴더만 사용한다. 성공 명령과 산출물 경로를 기록한다. |
| AC-13-02 | 배포 폴더에 wwwroot 웹 자산·로컬 폰트·Windows Skia 네이티브 파일과 필요한 고지가 있다. Linux RID 파일 존재를 Windows 지원 근거로 쓰지 않는다. |
| AC-13-03 | Windows 로컬 경로에서 virtual 기본 실행→브라우저 bootstrap→인공 샘플 PNG 생성을 확인하고 인터넷 차단 상태에서도 로컬 자산이 표시된다. |
| AC-13-04 | 가상 배포판 실행에 Node/.NET SDK/프린터 드라이버 설치를 요구하지 않는다. 실제 확인 환경과 self-contained 배포 근거를 기록하며 SDK 미설치 PC 미확인은 구분한다. |
| AC-13-05 | publish와 Windows 실행 결과를 별도 기록한다. Windows 검수 불가 또는 12번 미완료는 숨기지 않고 검증되지 않은 배포판을 완료품으로 표시하지 않는다. |

UI 재디자인, 설치 프로그램/서비스/자동 시작/자동 업데이트, 실제 프린터 출력, 외부 배포. 복잡한 네이티브 실패는 재현을 남기고 관련 모듈만 조사하며 무한 재시도하지 않는다. 13 handoff 뒤 멈춘다.
