# 06번 종료 후 전환 체크리스트

**실행 지시나 완료 기록이 아니다. 현재 06번 세션이 끝난 뒤에만 사용한다.** 기존 `tasks/06.md`의 요구를 확인 가능한 형태로 정리했으며 작업을 다시 구현하라는 뜻이 아니다.

06번 인계가 끝나면 `/ys-task 06 check`로 기존 구현·테스트·handoff와 아래 기준을 대조한다. 통과 근거가 유효한 항목은 같은 시험을 무조건 반복하지 않고, 미검증/변경 영향이 있는 부분부터 확인한다.

| ID | 통과 조건 | 확인 방법 |
| --- | --- | --- |
| AC-06-01 | 지연·장치 상태·시작 전 실패·N행 후 실패가 지정한 다음 virtual 작업 한 번에만 적용되고 physical 요청에는 적용되지 않음 | 인공 bitmap과 실제 API 요청; 다음 두 작업의 차이 확인 |
| AC-06-02 | 주입 지연은 렌더 제한과 분리되고 worker timeout/종료·host 재시작 뒤 늦은 성공이나 잠금 조기 해제가 없음 | 제한된 worker 중단/재시작 시험과 상태·프로세스 종료 근거 |
| AC-06-03 | 같은 UUID 재요청/응답 유실은 기존 작업으로 복구되고 다른 본문·동시 작업은 충돌 처리; 부분 실패가 rendered가 되지 않음 | API 응답과 backend 호출 횟수; 자동 재접수 없음 |
| AC-06-04 | TTL 10분·세션 3건/64MiB·호스트 128MiB·작업 32MiB 제한 및 정리/늦은 완료 경합을 지킴 | 조절 가능한 시계·경계값·지연 callback 시험; 조회로 TTL 연장 없음 |
| AC-06-05 | 진행 중 clear는 409; 정리 실패 후 다음 사용자에게 이전 이미지가 보이지 않고 재시작된 결과는 unavailable | clear 실패/재시작 복구 시험과 API 계약 확인 |
| AC-06-06 | 사진·base64·인증값이 로그/공개 경로/작업 메타데이터에 남지 않고 다른 세션의 artifact를 읽을 수 없음 | 인공 데이터로 보관 경로·인증·조회 거부 검사 |

05 handoff에 남은 브라우저의 인증→접수→폴링→Blob PNG 표시 확인과 간헐적인 프로필 저장 테스트 실패도 인계한다. 기존 02/05의 partial을 06의 테스트 통과만으로 done으로 바꾸지 않는다. 아직 못 본 Windows 화면은 그대로 미검증으로 남긴다.

현재 06번의 작성자가 작업 중이면 이 문서만 준비된 상태로 두고, 해당 코드·handoff·진행표·서버를 수정하거나 다시 실행하지 않는다.
