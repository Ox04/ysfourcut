## 바뀐 것
- `camera/captureSession.ts` — **순수 상태 머신**(React·DOM·타이머 무관). 3초 카운트다운, 슬롯 4개, 한 컷 재촬영, 취소, 전체 재촬영. `sessionId`(세션)·`captureToken`(셔터)으로 늦은 타이머·프레임을 무효화하고, 버릴 URL은 `release-url` 효과로 알린다.
- `camera/frameCapture.ts` — `coverCropRect`(object-fit: cover와 같은 크롭), `captureTargetSize`(확대 금지), `isFrameReady`(준비 전 검은 프레임 차단).
- `camera/errors.ts` — 권한 거부/장치 없음/사용 중/제약/비보안/미지원 → 한국어 안내 + 복구 동작. 원본 예외 메시지를 화면에 쓰지 않는다.
- `camera/useCamera.ts` — 스트림 수명, `devicechange`, track `ended`(장치 분리), 시작 토큰 경합 방지, **언마운트 시 토큰 무효화 + track 정지**.
- `camera/useCaptureSession.ts` — 순수 머신 ↔ 타이머·canvas 연결. blob URL 해제, `mountedRef` 가드, 프레임 대기 상한 2.5초, 캡처 실패 안내.
- `camera/CameraPreview.tsx` — `<video>`(mirrored, cover) + 오류 표시(`role="alert"` + 다시 시도).
- `booth/BoothFlow.tsx` — 07 화면에 실제 흐름 연결(시작→촬영→편집). `App.tsx`는 기본을 BoothFlow로 두고 `#scene=` 해시일 때만 07 디자인 미리보기를 연다.
- `CaptureScreen`에 `captureError` prop 추가(문구만, 07 배치·토큰 유지). `styles/booth.css`에 카메라 절 추가(토큰만 사용).
- 새 npm 의존성 없음. .NET·API 계약·렌더러 미변경.

## 독립 검수(Opus)와 반영
- **HIGH 2건 + MEDIUM 1건이 같은 원인**(언마운트가 진행 중인 비동기 경로를 무효화하지 않음): D1 getUserMedia 대기 중 언마운트 시 track 잔존(`liveTracks:1`), D2 프레임 미수신 시 rAF 60fps 무한 루프가 언마운트 후에도 지속, D3 toBlob 지연 중 언마운트 시 blob URL 누수. → `useCamera` 정리에서 시작 토큰 무효화, `useCaptureSession`에 `mountedRef` 가드(rAF·toBlob 양쪽) + 프레임 대기 상한으로 **전부 수정하고 실측 재검증**.
- MEDIUM D4(캔버스·toBlob 실패 시 `capturing`에 영구히 갇힘) → 실패 시 오류 문구 + 세션 취소로 복구.
- LOW D6(미완성 세션에서 한 컷 재촬영 시 사진을 든 채 idle) → `retakeCut`을 네 컷 완료 뒤에만 받도록 계약을 좁힘. D7(`useCamera` 반환값 매 렌더 새 객체) → `useMemo`. D8(버려질 프레임에도 플래시) → 실제 수락된 프레임에만. D9(캡처 중 문구가 상태를 잘못 전달) → "저장하는 중"으로 정정 + 오류 문구 연결.
- 검수의 긍정 확인: 순수 상태 머신 분리와 외부 관찰 기반 시험, StrictMode 안전성, 반전·크롭 일치, 사진 유출 없음.
