# 작업 인계 기록

작업 실행 전후 현재 번호의 `NN.md`를 이 폴더에 만든다. 이미 있는 실제 인계 기록을 보존한다. 07번부터 아래 AC 근거 형식을 사용하며 실행 중인 06번 기록은 전환 준비 세션에서 고치지 않는다. 로그 전체 대신 다음 내용을 30~40줄 안팎으로 남긴다.

```markdown
# NN — 작업 이름
상태: in_progress / done / partial / blocked
실행 환경: 실제 확인한 OS·런타임
사용 모델/effort: 실제 확인 가능할 때만 기록
실행 경로: 일반 Claude / OMC Execute / OMC Team 등 실제 호출한 경로

## 바뀐 것
- 파일과 핵심 변경

## 다음 작업이 알아야 할 계약
- API/타입/함수/설정 위치와 중요한 결정

## AC와 검증
| AC ID | 결과 | 근거 |
| --- | --- | --- |
| AC-NN-01 | PASS / FAIL / NOT_RUN / N/A | 실제 명령·테스트/브라우저 상태·환경·결과 또는 미실행 사유 |
- 현재 task의 모든 AC를 한 행씩 기록한다. 테스트 개수만으로 PASS를 쓰지 않는다.
- 화면·샘플·실제 웹캠·실물 프린터를 구분한다.
- 독립 검수: 담당/실제 모델/판정/수정 후 재검증, 미수행이면 그 사유

## 남은 것과 재개 위치
- 실패 재현, 시도한 해결과 결과, 다음 수정 위치
- 환경/사용자 확인이 필요한 조건
- 실행 중으로 남긴 자기 소유 서버의 식별 정보·포트·종료 방법 (비밀 인수 제외)
- 다음 입력: /ys-task NN (이어가기) 또는 검증 완료 후 다음 번호
```

테스트 성공을 추측하지 않는다. 사진·base64·인증값은 남기지 않는다. 자동 요약 때문에 원인 재현에 필요한 사실이 빠지면 줄 수보다 정확성을 우선한다. 한 작업마다 남겨 `/clear` 뒤에도 해당 파일만 읽고 이어갈 수 있게 한다.
