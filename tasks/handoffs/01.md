## 다음 작업이 알아야 할 계약
- API는 상대 경로 `/api/...`만 쓰고 Vite가 전부 프록시한다. `GET /api/health` 외 엔드포인트는 아직 없다. 02번에서 인증/세션에 맞춰 health를 포함해 정리한다.
- CORS는 `Program.cs` 상단 `DevCorsPolicy`/`DevOrigin` 상수로 관리하며 Development 환경에서만 적용됨. 운영 빌드에는 CORS 미들웨어 자체가 등록되지 않음(같은 오리진에서 서빙되므로).
- `dotnet` 바이너리 위치는 PATH에 없다. 새 셸에서 직접 쓰려면 `export PATH="$HOME/.dotnet:$PATH"` 필요(`docs/ENVIRONMENT.md` 참고). `npm run dev`는 이 export 없이도 동작(`scripts/dev.mjs`가 `~/.dotnet/dotnet`을 자동으로 찾음).
- SERVICE_DESIGN.md 11절의 `Api/ Jobs/ Profiles/ Printing/ Rendering/ Artifacts/` 하위 폴더는 아직 만들지 않았다. 02번 이후 실제 코드가 생길 때 함께 만든다.

## 검증
- `npm install`(Node 24.19.0): 성공, lockfile 생성.
- `npm run typecheck` / `npm run lint` / `npm run test`(Vitest 1개) / `npm run build`(Vite 프로덕션 빌드): 전부 성공.
- `dotnet build apps/print-host/YsFourcut.Host.csproj`: 성공(0 경고/0 오류).
- `npm run dev` 실제 실행: `dotnet run`이 자식 프로세스 `YsFourcut.Host`를 띄우고 `Now listening on: http://127.0.0.1:4317` 로그 확인. Vite `ready` 로그 확인.
- `curl http://127.0.0.1:4317/api/health` 직접 호출과 `curl http://127.0.0.1:5173/api/health -H "Origin: http://127.0.0.1:5173"`(Vite 프록시 경유) 둘 다 200 + `{"status":"ok","printerMode":"virtual","environment":"Development"}`. 프록시 경유 응답에 `access-control-allow-origin: http://127.0.0.1:5173` 확인.
- `Origin: http://evil.example`로 같은 호출: 본문은 오지만 `access-control-allow-origin` 헤더 없음(정상 CORS 동작, 브라우저가 스크립트 접근을 차단).
- 종료 정리: `dev.mjs`에 `SIGINT` 전달 → `dotnet run`, 실제 앱 프로세스 `YsFourcut.Host`, `vite`, `dev.mjs` 전부 종료 확인(`ps`). `ss -tlnp`로 4317/5173 포트 닫힘 확인. 같은 SDK의 무관한 `VBCSCompiler` 공유 빌드 서버는 그대로 남아있음(이 앱이 관리하는 프로세스가 아니므로 정상).

## 남은 것과 재개 위치
- Windows 루프백·화면 연결 확인 완료. 기본 WSL NAT localhost forwarding이 동작하므로 portproxy/방화벽/`.wslconfig` 변경 없이 해결했다. 개발 서버는 실행 상태로 두었으며 다음 작업에서 같은 포트로 중복 실행하지 않는다. 종료·재시작 후에는 README의 실행 절차를 따른다. 상세 확인 기록은 `docs/ENVIRONMENT.md` 참고.
- Fedora 42가 .NET 공식 지원 배포판 목록에 포함됐는지는 재확인하지 않았다. 이번 사용자 범위 설치는 성공했지만 공식 지원 여부와는 무관하다.
- 02번(API·인증·프로필)에서 이어감. 02번에서 자동으로 진행하지 않는다.
