## 독립 검수와 반영
- 검수 판정: **HIGH 0건**, AC-09-01~05 전부 PASS 재확인. 지적 3건만 수정했다(새 기능·리팩터링 없음).
- MEDIUM-1 `photoWorkerClient.ts` — Worker가 죽어도 `this.worker`를 비우지 않아 다음 요청이 영원히 미결이 되고 합성 큐가 멈추던 문제. `onerror`에서 Worker를 버리고 대기 요청을 `WORKER_FAILED`로 끝내며, `terminate()`도 `WORKER_TERMINATED`로 정리한다. Worker 생성 방법을 주입 가능한 인자로 바꿔 실패를 시험할 수 있게 했다. 새 시험 `photoWorkerClient.test.ts` 4건(실패 뒤 새 Worker로 복구 / terminate가 미결을 남기지 않음 / 생성 실패는 명시적 오류이고 재시도 / forget한 응답 무시). 실브라우저 실측: 깨진 module Worker로 첫 요청 `WORKER_FAILED` → 두 번째 요청이 새 Worker에서 정상 완료(Worker 생성 2회).
- LOW-3 `useStripComposition.ts` — 취소·교체된 revision의 실패는 `setError`하지 않는다(현재 running일 때만 표시).
- LOW-7 `BoothFlow.tsx` — 저장 링크를 문서에 붙였다가 누르고 제거한다.
- **고치지 않고 넘기는 항목**(10/11번): MEDIUM-2 합성 배선 층(hook·textLayer·photoSource)의 자동 시험 공백 — 현재는 헤드리스 실측으로만 덮는다. 새 DOM 시험 환경(jsdom 등) 도입은 의존성 추가라 11번 판단으로 미뤘다. LOW-4 폰트 로딩 실패가 캐시돼 재시도되지 않음, LOW-5 `tone.ts`의 도달 불가 상한 검사, LOW-6 문구 카운터가 UTF-16 길이(합성은 코드 포인트 기준으로 이미 정확), LOW-8 07 개발 미리보기가 편집 장면이 아닐 때도 합성.

## 다음 작업이 알아야 할 계약
- 10번: `useStripComposition`이 돌려주는 `composition.bitmap`을 `toPrintJobBitmap()`으로 감싸 `api.submitPrintJob`에 그대로 넣으면 된다(별도 재합성 금지). `composition.previewUrl`은 저장·표시용이며 훅이 수명을 관리한다. `EditScreen.onPrint`는 아직 비활성이고 `printReady={false}`다.
- 프로필은 `usePrinterProfile()`이 읽는다. `contentWidthDots`가 없으면 합성하지 않고 이유를 표시한다(폭을 추측하지 않는다).
- 합성은 설정 변경 150ms 디바운스 + revision 검사로 한 번만 돈다. Worker는 훅이 만들고 언마운트에서 종료한다.
- fixture 갱신: `YSFOURCUT_UPDATE_FIXTURES=1 npm run test --workspace packages/imaging` (없으면 `.NET` 시험이 불일치로 실패한다).
- **10번 경고(수정분 재검수 지적)**: `EditScreen`의 `busy`를 합성 상태에 묶으면(`busy={strip.isComposing || submitting}`) 합성이 멈췄을 때의 유일한 탈출구인 `전체 다시 찍기`가 같이 잠겨 새로고침 외 복구가 불가능해진다. `busy`를 합성 상태로 넘길 거면 같은 변경에서 `photoWorkerClient.dither()`에 워치독(N초 → `discardWorker()` + `WORKER_TIMEOUT` reject)을 함께 넣어야 한다. 이벤트가 발생하는 실패는 이미 전부 닫혔고, 남은 방아쇠는 브라우저의 조용한 Worker 종료뿐이다.
- `photoWorkerClient.forget(revision)`은 **이미 결착된 요청**에만 부른다. 진행 중인 revision에 부르면 그 promise가 영구 미결이 된다.
