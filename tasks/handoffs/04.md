## 바뀐 것
- `Rendering/ReceiptAppearanceRenderer.cs` 신설 — `appearance.png` 생성. 합성 순서는
  바닥 그림자 → 종이색 → 섬유 질감 → (선택) 밴딩 → 잉크(원본 지면 Multiply) → (선택) 번짐 → 가장자리.
  **Multiply**로 올리므로 검정 dot는 검정 그대로, 흰 여백만 종이색이 된다.
- 절취 외형 3종: `straight`(수평 절단), `tear`(이송 여백 안에서만 흔들리는 불규칙선), `none`(캔버스 끝까지 이어지는 미절취 롤).
- 추정 효과 `ink_bleed`/`banding` 구현하되 **기본 꺼짐**, 알 수 없는 효과 이름은 거부. content/paper에는 적용하지 않는다.
- `IReceiptAppearanceRenderer`에 `Measure(layout)` 추가 — 그리기 **전에** 픽셀 한도를 검사하기 위함(03번 인터페이스 변경점).
- `ReceiptRenderer.Render(..., estimatedEffects)` 추가, 외관 생성 전 `Measure`로 한도 검사 + 생성 후 PNG 헤더로 크기 재확인.
- `Program.cs`의 DI를 `UnimplementedAppearanceRenderer` → `ReceiptAppearanceRenderer`로 교체. 호스트 버전 0.4.0.
- `RenderInspectionTool`을 80/58mm × 절취 3종 × 짧은/긴 내용 + 효과 조합으로 확장(환경 변수 지정 시에만 파일 생성).
- `docs/RECEIPT_APPEARANCE.md` 신설, `docs/API_CONTRACT.md` 렌더링 절 갱신.
- 테스트 `ReceiptAppearanceTests.cs` 14개 추가. 03번의 fallback 테스트 이름을 실제 의미에 맞게 변경.

## 다음 작업이 알아야 할 계약
- 캔버스: `(paperWidthDots + 48) × (paperHeightDots + 48)`, 종이 원점 `(24, 24)`, 배율 1:1.
  **배경은 투명**이고 바닥 그림자만 들어 있다. 07/12는 중간 톤 배경 위에 올려야 종이가 살아난다.
- 바깥 여백·그림자는 **물리 mm에 미포함**. 80mm의 576×1788 내용은 그대로 640×1876dot / 80×234.5mm다.
- `appearanceRevision = "a1"`. 질감·절취선은 `seed`에만 의존하므로 05번은 작업에 seed와 revision을 스냅샷으로 저장해야 재조회 시 같은 그림이 나온다.
- `EstimatedEffects.InkBleed`/`Banding`만 유효한 이름이다. 06번이 UI로 켤 때 이 목록을 그대로 쓴다.
- 색·파라미터·검수 이미지 재생성 명령은 `docs/RECEIPT_APPEARANCE.md`에 있다. 07/12가 이 문서를 이어 쓴다.

## 검증
- `npm run test:all`: .NET **92개**(78 + 외관 14), 웹 8개 전부 통과. 빌드/typecheck/lint 통과.
- 테스트가 확인한 것: 캔버스 = 지면 + 사방 24px, content/paper 바이트가 외관 유무와 **완전히 동일**,
  잉크 dot는 `(0,0,0)` 유지·흰 여백은 밝은 종이색(R≥235) 유지, 절취 3종 모두 내용 최상단/최하단 행을 자르지 않음,
  같은 seed는 동일 바이트·다른 seed는 다름, 효과 기본 꺼짐(기본 == 빈 목록), 알 수 없는 효과 거부,
  종이 밖은 알파 0, 외관 픽셀 한도를 그리기 전에 검사(kind=appearance), 80/58mm·짧은(48dot)/긴(1788dot) 내용에서 내용 네 모서리가 종이 위에 있음.
- **눈으로 확인한 것**(생성 코드 작성과 구분해 기록): `80-straight`, `80-tear`, `80-none`, `58-straight`, `80-long`(688×1924), 효과 on/off 비교, 그리고 `paper` vs `appearance`의 상단 1:1(2배 확대) 나란히 비교 이미지를 실제로 열어 확인했다. 1픽셀 디더 패턴이 보간 없이 그대로 보이고, 절취면이 내용에 닿지 않으며, 종이색이 대비를 떨어뜨리지 않음을 확인했다.
- 픽셀 측정으로 확인: 종이 여백 색은 `(250,247,241)`~`(247,244,238)` 네 단계뿐(아주 약한 질감), 검정은 `(0,0,0)`, 캔버스 모서리 알파 0.
- 인공 패턴만 사용했고 실제 인물 사진은 쓰지 않았다. 외부 서비스 업로드 없음. 검수 이미지는 스크래치 폴더에만 만들고 저장소에 커밋하지 않았다.
- 호스트 재기동: `npm run dev`로 `hostVersion=0.4.0` health 200 확인. 외관 렌더러 DI 교체가 기동을 막지 않는다.
