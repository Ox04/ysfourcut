상태: partial (WSL에서 API·인증·검증 전부 실제 확인. Windows 브라우저 화면에서의 인증 성공만 사용자 확인 필요)

## 다음 작업이 알아야 할 계약
- 전체 경로·타입·오류·구현 상태는 `docs/API_CONTRACT.md`에 있다. C#(`Contracts/`)과 TS(`apps/web/src/api/contract.ts`)는 짝이므로 한쪽만 바꾸지 않는다.
- 모든 `/api` 요청에 `X-YSFourcut-Client: web` 필요. 변경 요청은 정확한 Origin + `application/json`(본문 없어도 `{"schemaVersion":1}`). 본문 1MiB 상한.
- 인증: `GET /pair` → 302로 앱 주소 `#bootstrap=<코드>` → 웹이 주소에서 지우고 `POST /api/bootstrap` 교환 → 세션 쿠키. 코드는 60초·1회. fragment는 서버로 안 가므로 로그에 코드가 남지 않는다.
- `POST /api/print-jobs`는 **검증까지만 실제로 수행**하고 통과해도 501 `NOT_IMPLEMENTED`(`details.validated=true, accepted=false`)다. 05번이 접수·잠금·상태를 붙이면 된다. 검증기와 `sourceDigest` 계산은 `Jobs/PrintJobRequestValidator.cs`에 그대로 재사용한다.
- revision = 인쇄 핵심 설정만의 해시(`r1-<hex16>`), 표시 이름·메모 제외, 재시작해도 동일. 03/05번의 작업 스냅샷은 이 값을 그대로 비교하면 된다. 기본 프리셋 80mm는 640/576/32/24/64dot, 203.2DPI다.
- 프로필 설정 저장 위치: `~/.config/YSFourcut/printer-profile.json`(임시 파일+rename). 작업 기록용 state 경로는 `AppDirectories.ResolveStateDirectory`가 이미 있다(아직 미사용, 05/06번용).
- 알려진 성질: 쿠키는 포트를 구분하지 않으므로 같은 PC의 다른 127.0.0.1 서버에도 전송될 수 있다. SERVICE_DESIGN 10절이 인정한 "로컬 PC 계정 신뢰 범위"를 넘지 않는다는 뜻이며, 이를 더 좁히려면 별도 설계 변경이 필요하다.

## 검증
- `npm run typecheck` / `npm run lint` / `npm run build` / `npm run test`(웹 8개) / `npm run test:host`(.NET 65개): 전부 성공.
- .NET 테스트가 실제로 확인한 것: health 비인증 최소 응답·no-store, Host 위조 403, 전용 헤더 누락 403, Origin 없음·위조 403, 비 JSON 415, 1MiB 초과 413, 잘못된 JSON 400, 페어링 fragment 전달, 쿠키 속성(HttpOnly/SameSite=Strict/Path/Domain 없음), 코드 재사용·60초 만료·불명 코드 거부, **코드와 쿠키 값이 로그·응답 본문에 없음**, 세션 필요 401, 프리셋 2종·`osQueryPerformed=false`·`hardwareVerified=false`, 80mm 기하 값, 프로필 저장·재로드·원자적 쓰기(.tmp 미잔존), 잘못된 revision 409, 없는 프로필 404, 잘못된 cutStyle 400, print-job의 stride/padding/길이/base64/서비스·프로필 상한/UUID/revision 거부와 정상 요청의 501, 501 경로들, Linux physical 시작 거부, revision 결정성.
- 실서버(WSL, `npm run dev`) + curl로 Vite 프록시를 지나는 흐름을 직접 확인: 인증 전 401 → `/pair` 302(fragment) → 교환 200 + Set-Cookie → 프로필/프린터 조회 200 → 같은 코드 재사용 401 → 전용 헤더 누락 403 → Origin 위조 403 → Host 위조 403 → print-job 정상 501·padding 400·revision 409. `/pair`는 전용 헤더 없이(브라우저 내비게이션처럼) 302를 반환한다.
- 서버 로그 실제 확인: 코드·쿠키·base64 흔적 0건. 실패 경로는 `AlreadyUsed`처럼 결과 이름만 남는다.
- **미실행**: Windows Chrome/Edge에서 화면을 열어 `로컬 프로그램과 연결하기` → 프로필 표시까지 눈으로 확인. 이번 세션은 WSL 셸 도구만 사용했다. HTTP 단계는 모두 확인했지만 브라우저 실제 동작(특히 fragment 제거와 쿠키 저장)은 사용자 확인이 필요하다.
- **미실행**: Skia/PNG(03번), 작업 접수·큐(05번), 실물 인쇄(91번).
