# 11 — 통합 검수와 핵심 결함 수정

- 권장 모델: **Opus 5 / high**
- 입력: `11 진행해`
- OMC 입력: `/ys-task 11` — 독립 검수를 나눌 때만 `/ys-task 11 team`.
- 선행 작업: 10.
- 목표: 실제 앱의 기능·이미지·실패·개인정보 조건을 재현 가능하게 검증.

## 이번에 읽을 것

- 진행표, 10 handoff, 실행 명령, 기존 테스트와 실패에 관련된 코드.
- `VIRTUAL_PRINTER_DESIGN.md`의 12절.
- `IMPLEMENTATION_OUTLINE.md`의 8절 중 소프트웨어 체크리스트.

## 할 일

1. 실제 프로젝트의 build/typecheck/lint/test와 .NET 테스트를 실행하고 의미 있는 누락 검증만 추가한다. 구현과 같은 식을 반복하는 형식적인 테스트는 늘리지 않는다.
2. 실제 Linux .NET을 띄우는 E2E를 수행한다. 샘플 카메라를 쓸 수 있지만 API stub으로 성공을 흉내 내지 않는다.
3. 사진 4장/재촬영, 한글/레이아웃, 입력↔content↔paper crop, 폭/이송/마지막 행, 실제 appearance 응답을 확인한다.
4. UUID 연타/충돌, 프로필 변경, 응답 유실, worker timeout/중단, host 재시작, 부분 실패를 재현하고 자동 중복 작업/잘못된 성공이 없는지 확인한다.
5. 인증 없는/다른 세션 조회, TTL·용량 초과·명시적 clear·늦은 callback 경합과 로그/디스크 저장 여부를 검사한다. .NET 중지 실패와 Windows 큐 미호출도 포함한다.
6. 발견한 기능 결함은 재현을 남기고 현재 검수 범위 안에서 최소 수정한다. UI를 다시 디자인하거나 사전 필요 없는 아키텍처 교체를 하지 않는다.
7. `docs/VALIDATION.md`에 명령·결과·환경·미확인 항목을 요약한다. 실제 Windows 브라우저/웹캠 검수는 자동 샘플 테스트와 구분한다.

## Acceptance Criteria — 완료 확인

[공통 완료 기준](DEFINITION_OF_DONE.md)을 적용한다. 변경 범위는 검증/재현 가능한 결함의 최소 수정/VALIDATION이다. Team 선택 시 [역할·공유 서버 규칙](OMC_WORKFLOW.md)을 지킨다.

| ID | 통과 조건·검증 |
| --- | --- |
| AC-11-01 | 실제 package.json 기준 웹/.NET build/typecheck/lint/test가 통과한다. 실패·간헐 실패의 재현/결과를 기록하고 총 테스트 개수만으로 완료시키지 않는다. |
| AC-11-02 | API stub 없이 실제 Linux host/worker를 사용하는 E2E로 네 컷·재촬영·한글·최종 bitmap→content→paper crop과 appearance 응답을 확인한다. |
| AC-11-03 | UUID 충돌/응답 유실/프로필 변경/worker timeout·중단/host 재시작/부분 실패를 재현해 중복 실행·잘못된 rendered가 없음을 확인한다. |
| AC-11-04 | 무인증·다른 세션 조회, TTL/용량/clear/늦은 callback 경합, .NET 중단, 로그·디스크 보관을 검증한다. virtual 경로가 Windows 인쇄 큐를 호출하지 않는다. |
| AC-11-05 | 실제 Windows 브라우저·웹캠의 검수 범위를 자동 샘플 시험과 구분한다. 필수 환경 검수 미실행은 NOT_RUN/partial로 남기며 미준비 실물 프린터는 virtual 완료 조건에 넣지 않는다. |
| AC-11-06 | `docs/VALIDATION.md`와 handoff에 AC별 명령/결과/환경/미해결 결함을 기록한다. 결함 수정 후 관련 회귀를 갱신하고 사진·base64·토큰을 근거에 포함하지 않는다. |

## 이번에 하지 않을 것

디자인 전면 수정, 과도한 테스트 추가, 모든 로그를 대화에 붙이기, 실제 인쇄, 배포. 11 handoff를 남기고 멈춘다.
