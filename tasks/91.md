# 91 — Windows 실물 어댑터와 종이 검수

- 권장 모델: **Opus 5 / high**
- 입력: `91 진행해`
- OMC 입력: `/ys-task 91` — 90번의 장치/경로 확인 후에만 사용한다.
- 선행 작업: 90의 장치/경로 근거, 실행 가능한 가상 버전.
- 목표: 같은 웹 API와 비트맵 아래에 검증된 실물 출력 경로 연결.

## 이번에 읽을 것

- 진행표, 90 handoff, `docs/PRINTER_REFERENCE.md`, 관련 API/프로필/worker 코드.
- `SERVICE_DESIGN.md`의 6~10절 중 실제 인쇄 계약.
- `IMPLEMENTATION_OUTLINE.md`의 8절 중 실제 프린터 검수.

## 할 일

1. 90에서 결정한 어댑터 하나만 구현한다. GDI이면 byte stride→DWORD DIB, 팔레트/방향, 장치 DC/DPI/영역/용지 길이 검사를 지킨다.
2. 한 스트립을 한 작업/한 페이지/한 부로 보내고 드라이버와 별도 커팅 명령을 중복 사용하지 않는다. 용지/이미지를 자동으로 축소해 설정 불일치를 숨기지 않는다.
3. Windows worker의 OS 제출/큐 추적/timeout/outcome_unknown을 실제 상태로 관리한다. submitted를 물리적 출력 완료로 표시하지 않는다.
4. 작은 패턴부터 검수하고 이후 네컷 3회·재연결·하단 이송/절취를 확인한다. 실제 검수한 profile revision만 hardware 검증으로 저장한다.
5. 예외·부분 전송·재시작에서 자동 재인쇄/다른 큐 대체가 없음을 확인한다. 불명확한 작업은 종이/해당 OS 큐 확인 뒤 복구한다.
6. 가상 모드가 계속 Linux/Windows에서 동작하고 실제 프린터를 건드리지 않는지 회귀 확인한다. UI 디자인은 변경하지 않는다.

## Acceptance Criteria — 완료 확인

[공통 완료 기준](DEFINITION_OF_DONE.md)을 적용한다. 변경 범위는 확인된 Windows 어댑터/worker·실물 프로필·검수 기록이다.

| ID | 통과 조건·검증 |
| --- | --- |
| AC-91-01 | 90에서 정한 어댑터 하나를 같은 API/bitmap 아래 연결한다. GDI라면 DIB stride·방향·팔레트·DPI/용지 영역을 확인하고 불일치를 자동 축소로 숨기지 않는다. |
| AC-91-02 | 한 스트립이 작업/페이지/부수 각 하나로 제출되고 중복 커팅이 없다. submitted/실제 출력/unknown을 구분하며 실패·재시작에서 자동 재인쇄하지 않는다. |
| AC-91-03 | 실제 장치에서 작은 패턴→네컷 3회→재연결·하단 이송/절취를 확인한다. 모델·드라이버·폭·품질·profile revision과 확인 결과를 기록하고 해당 revision만 검증됨으로 표시한다. |
| AC-91-04 | virtual 회귀가 Linux/Windows에서 통과하고 실제 큐를 호출하지 않는다. 장치 없이 소프트웨어만 검증한 결과를 실물 완료로 기록하지 않는다. |

## 이번에 하지 않을 것

전송 방식 전체 선제 구현, 드라이버 무단 교체, 다른 앱 작업/전체 큐 삭제, 웹 API/디자인 전면 교체. 91 handoff를 남기고 멈춘다.
