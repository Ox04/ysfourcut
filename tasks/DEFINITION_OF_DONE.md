# 공통 완료 기준 — Definition of Done

07번 이후에는 해당 task의 Acceptance Criteria(AC)와 이 문서를 함께 사용한다. 실행 중인 06번에 새 절차를 끼워 넣지 않는다. 06번 인계 후 확인할 항목은 [전환 체크리스트](acceptance/06.md)에 있다.

## 시작 조건

- task의 목표·선행 계약·하지 않을 일을 확인하고 변경할 모듈과 검증 방법을 짧게 정한다. 기존 task가 충분하면 별도 인터뷰/전체 PRD/합의 회의를 만들지 않는다.
- 선행 `partial`의 이유를 읽는다. 단순 환경 미검수와 현재 구현을 막는 계약 결함을 구분한다. 후자를 해결하지 않고 가짜 데이터로 통과하지 않는다.
- 실행 중인 다른 Claude 세션·서버·worker를 자기 소유로 간주하지 않는다. 이미 사용하는 5173/4317 서버를 무단 재시작하거나 같은 포트로 중복 실행하지 않는다.

## PASS에 필요한 근거

| 구분 | 필요한 근거 |
| --- | --- |
| 동작 | 입력/조작, 기대 결과, 실제 결과. 필요한 경우 실제 .NET 및 별도 worker를 사용 |
| 자동 검증 | 실제 명령, 관련 테스트 이름/파일, 성공·실패 결과. 총 테스트 개수만으로 AC를 통과시키지 않음 |
| 화면 | 사용한 브라우저·화면 크기·상태와 직접 확인한 결과. 코드 리뷰만으로 시각 AC를 통과시키지 않음 |
| 이미지 | 합성 샘플의 크기·좌표·픽셀 비교 등 검사 결과. 사진이나 base64는 기록하지 않음 |
| 환경 | WSL 자동 시험 / Windows 브라우저 / 실제 웹캠 / Windows 실행 / 실제 프린터를 구분 |

AC는 명세이므로 task 파일에서 완료 체크를 누적하지 않는다. 결과는 `tasks/handoffs/NN.md`에 `AC-번호-순번 / PASS·FAIL·NOT_RUN·N/A / 근거`로 기록한다. N/A는 해당 조건이 실제로 적용되지 않을 때만 이유를 적으며, 필수 검수를 못 한 경우는 NOT_RUN이다.

## 필요한 검증만 실행

- 2026-08-31 현재 명령: 웹/이미지 `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build`; .NET `npm run build:host`, `npm run test:host`. 실행 시 package.json과 실제 테스트 설정이 기준이다.
- 작은 변경은 해당 모듈의 테스트부터 실행한다. 문서만 바꿨으면 경로·링크·명령을 대조하고 전체 빌드를 반복하지 않는다. 테스트 개수나 문서 분량을 목표로 삼지 않는다.
- 11번은 웹/.NET 전체 검증과 실제 API E2E를 한 번 통합 수행한다. 서로 같은 출력 디렉터리를 쓰는 .NET build/test, 같은 서버를 중단·초기화하는 시험은 동시에 실행하지 않는다.
- 의미 없는 sleep 대신 조절 가능한 시계와 제한된 실패 훅을 사용한다. 새 실패에는 재현이나 회귀 검증을 남기되 구현식을 그대로 복사한 테스트는 추가하지 않는다.
- 마지막 관련 수정 이후의 근거가 필요하다. 기존 handoff의 결과는 재사용 가능성을 판단하는 자료이며 새 변경의 자동 PASS 근거가 아니다.

## 완료·중단 조건

- `done`: 현재 task의 필수 AC가 전부 PASS이고 미해결 필수 결함이 없으며 변경/검증/남은 환경 제한을 저장했다. OMC 실행은 별도 검수 결과도 기록한다.
- `partial`: 산출물은 있으나 필수 Windows·카메라 등 검수가 NOT_RUN이거나 완료 조건이 남았다. 구현한 부분은 보존하고 정확한 재개 위치를 남긴다.
- `blocked`: 현재 범위에서 더 진행할 수 없는 구체적인 외부 조건이나 선행 결함이 있다. 모든 가능한 작업을 먼저 마친다.
- 같은 원인에 대한 수정이 두 번 실패하면 세 번째부터 같은 시도를 반복하지 않는다. 새 증거를 얻는 작은 진단을 한 번 수행하고, 원인 불명이 계속되면 재현/시도/대상 번호를 남겨 99번으로 인계한다. 자동으로 고가 모델이나 장기 루프를 시작하지 않는다.
- AC를 만족시키기 위해 테스트를 삭제/skip하거나 인증·실패 처리를 완화하지 않는다. 명세가 실측 사실과 모순되면 원문·근거·수정 이유를 기록한다. 사용자 요구를 축소하는 변경은 완료로 포장하지 않는다.
- 보고는 변경 요약, AC 결과, 실제 검증, 남은 항목, 다음 입력 한 줄로 끝낸다. 다음 번호는 자동 실행하지 않는다.

사진·PNG·base64·인증 토큰을 task/PRD/검수 기록/OMC 프롬프트에 넣지 않는다. 시각 증거를 저장해야 하면 개인 사진 대신 명시적인 인공 샘플만 사용한다.
