# 10 — 촬영부터 가상 출력까지 연결

- 권장 모델: **Opus 5 / high**
- 입력: `10 진행해`
- OMC 입력: `/ys-task 10`
- 선행 작업: 06, 07, 08, 09.
- 목표: 사용자가 앱에서 한 사이클을 실제로 완료할 수 있음.

## 이번에 읽을 것

- 진행표, 06/07/09 handoff와 실제 API/화면 상태/합성 계약.
- `VIRTUAL_PRINTER_DESIGN.md`의 7~9절, `SERVICE_DESIGN.md`의 4절·9~10절.

## 할 일

1. 시작 → 카메라/샘플 → 4컷 → 재촬영/편집 → 최종 미리보기 → 가상 출력 → 결과 → 다음 촬영을 연결한다. 07에서 남긴 개발 fixture는 제품 흐름에서 제거한다.
2. 클릭 시 bitmap/profile revision/UUID를 고정하고 실제 POST로 보낸다. 응답 유실은 같은 ID 조회부터 하며 새 ID로 자동 재인쇄하지 않는다.
3. 실제 상태를 조회하고 인증 fetch로 서버 PNG를 받아 Blob URL로 표시한다. .NET이 꺼지거나 필수 이미지가 없으면 가상 성공을 표시하지 않는다.
4. 출력 중 버튼/설정/세션 변경을 막는다. 확정 실패 이후에만 사용자 재시도를 허용한다. 가상 실패에 실제 종이 확인을 요구하지 않는다.
5. 가상 80/58mm 선택과 오류 시험 패널을 실제 API에 연결하고 가상 모드/주입 오류임을 상시 표시한다.
6. PNG 다운로드는 사용자 선택으로만 한다. 다음 촬영과 120초 유휴 정리는 서버 clear + 브라우저 원본/합성/URL 정리를 함께 수행한다. 삭제 실패 때 다음 사용자로 넘어가지 않는다.
7. 권한 거부, 사진 준비 안 됨, 프로필 변경, 출력 지연/실패, 만료 등 한국어 문구를 UI 디자인에 맞춰 연결한다. 새 UI 테마를 만들지 않는다.

## Acceptance Criteria — 완료 확인

[공통 완료 기준](DEFINITION_OF_DONE.md)을 적용한다. 변경 범위는 기존 촬영/합성/API/뷰어의 연결과 세션 정리다.

| ID | 통과 조건·검증 |
| --- | --- |
| AC-10-01 | Windows 브라우저→WSL 실제 .NET에서 촬영 또는 표시된 샘플→네 컷→편집→출력→세 PNG 결과→다음 사용자 사이클을 수행한다. 샘플 성공을 실제 웹캠 검수로 기록하지 않는다. |
| AC-10-02 | 최종 bitmap/profile revision/UUID를 클릭 시 고정한다. 연타·응답 유실·재접속에서도 같은 작업을 조회하고 backend 실행이 중복되지 않는다. |
| AC-10-03 | .NET 중단/필수 PNG 누락/가상 오류에서 성공을 표시하지 않는다. 출력 중 설정·세션 변경을 막고 확정된 실패 후에만 재시도할 수 있다. |
| AC-10-04 | 실제 인증 fetch/Blob으로 appearance를 표시하고 미리보기와 서버 content가 일치한다. 가상 80/58mm와 오류 패널이 실제 API에 연결되고 제품 흐름에 성공용 stub이 없다. |
| AC-10-05 | 다음 촬영/120초 유휴 정리가 서버와 브라우저 원본·합성·Blob URL을 정리한다. 삭제 실패·늦은 callback에서도 다음 사용자에게 사진이 재표시되지 않는 검증이 통과한다. |
| AC-10-06 | PNG 저장은 사용자 동작으로만 수행된다. 07 디자인을 유지하고 관련 웹/.NET 회귀 검증과 실제 한 사이클의 근거를 기록한다. |

## 이번에 하지 않을 것

구조 전체 리팩터링, 프레임 재디자인, Windows 실물 인쇄, 외부 다운로드 서버. 10 handoff를 남기고 멈춘다.
