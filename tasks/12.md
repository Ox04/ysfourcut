# 12 — 실제 화면과 영수증 디자인 마감

- 권장 모델: **Fable 5 / high**
- 입력: `12 진행해`
- OMC 입력: `/ys-task 12` — Fable 메인 세션에서 직접 마감한다.
- 선행 작업: 10, 11의 핵심 기능 검수. 실물 AHAPOS 검수는 필요 없다.
- 목표: 실제 데이터/오류/다양한 화면 크기에서 04·07 디자인을 한 번 마감.

## 이번에 읽을 것

- 진행표, 07/10/11 handoff 중 화면 관련 내용.
- `docs/UI_DESIGN.md`, `docs/RECEIPT_APPEARANCE.md`, 관련 컴포넌트와 appearance 코드.
- `docs/VALIDATION.md`의 남은 문제와 실제 앱 화면/서버 PNG.

## 할 일

1. 돌아가는 앱에서 촬영·편집·결과·실패·다음 사용자 화면을 직접 본다. 코드만 읽고 디자인 검수 완료로 보고하지 않는다.
2. 실제 촬영 또는 명확한 개발 샘플을 사용해 얼굴 영역/긴 한글/4컷, 80/58mm 영수증, 큰/작은 브라우저 크기를 비교한다. 사용자 사진은 외부 업로드/자동 파일 저장하지 않는다.
3. 잘림·간격·계층·문구 길이·버튼 크기·포커스·로딩/오류 강조를 다듬는다. 기존 토큰/방향을 완성하며 새 스타일 후보나 전면 재디자인을 시작하지 않는다.
4. 종이 질감·그림자·절취가 내용과 경쟁하면 appearance 파라미터만 조정한다. content/paper 픽셀과 물리 치수는 변경하지 않는다.
5. 서버 준비 전에 출력 성공처럼 보이는 효과, 가상임을 숨기는 표현, 보기 어려운 명암을 없앤다. reduced-motion과 키보드 동선을 확인한다.
6. 바뀐 UI/외관과 직접 관련된 검증을 다시 실행하고 디자인 문서의 실제 값만 갱신한다. 백엔드 결함 발견 시 별도로 재현을 남기고 디자인 작업을 기능 재개발로 키우지 않는다.

## Acceptance Criteria — 완료 확인

[공통 완료 기준](DEFINITION_OF_DONE.md)을 적용한다. 변경 범위는 기존 UI와 appearance 파라미터, 대응 디자인 문서다.

| ID | 통과 조건·검증 |
| --- | --- |
| AC-12-01 | 실제 앱에서 촬영/편집/결과/실패/다음 사용자 상태를 직접 본다. 1280×800·390×844, 긴 한국어 문구와 80/58mm 결과의 확인 범위를 기록한다. |
| AC-12-02 | 기존 04/07 토큰·방향을 유지하면서 잘림/겹침/주요 버튼 48px/포커스·키보드 동선을 확인한다. reduced-motion과 로딩/오류 표현이 동작한다. |
| AC-12-03 | appearance 변경 전후 같은 합성 샘플의 content/paper 픽셀과 물리 치수가 동일하다. 질감·그림자·절취 조정이 사진과 글자 내용을 바꾸지 않는다. |
| AC-12-04 | 서버 완료 전 성공 표현이나 가상 모드를 숨기는 문구가 없다. 검수용 사용자 사진을 외부 업로드하거나 자동 저장하지 않는다. |
| AC-12-05 | 바뀐 값과 관련 회귀 검증을 디자인 문서/handoff에 기록한다. 못 본 상태는 NOT_RUN이며 발견한 핵심 기능 결함은 원인 작업에 인계한다. |
