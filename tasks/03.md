# 03 — 정확한 흑백·용지 PNG

- 권장 모델: **Opus 5 / high**
- 입력: `03 진행해`
- 선행 작업: 01, 02.
- 목표: 입력 1비트와 픽셀이 같은 content PNG, 정확한 크기의 paper PNG.

## 이번에 읽을 것

- 진행표, 02 handoff, 관련 타입/프로필, 있으면 03 handoff.
- `VIRTUAL_PRINTER_DESIGN.md`의 2절·4~6절.
- `SERVICE_DESIGN.md`의 5절 중 계산 예시.

## 할 일

1. `CrossEscPos.Rendering.Skia`/`CrossEscPos.Abstractions` 1.2.0을 우선 복원하고 Linux Skia 네이티브 로드를 실제로 확인한다. 라이선스와 패키지 버전을 고정한다.
2. `MonoBitmapDecoder`, 정수 dot 기반 `ReceiptLayout`, 얇은 Skia 어댑터, `ReceiptPaperComposer`를 구현한다. Core/FeedEscPos나 ESC/POS 인코더는 도입하지 않는다.
3. content는 MSB-first/1=검정/위에서 아래로 정확히 복원한다. paper는 순백 용지와 앞뒤 이송·비인쇄 여백만 더하고 재디더링·축소/확대하지 않는다.
4. 80mm 기본: 8dot/mm, paper 640dot, content 576dot, 좌우 32dot, 앞 24/뒤 64dot. 576×1788 입력이면 paper 640×1876, 80×234.5mm, 본문 원점 (32,24). 58mm 보조도 문서의 별도 값으로 구현한다.
5. 결과 픽셀/PNG 크기를 인코딩 전후 검사하고 8백만 픽셀/작업 PNG 합계 32MiB 한도를 지킨다. 모든 버퍼·canvas·stream을 dispose한다.
6. 04번에서 쓸 appearance 생성 인터페이스와 레이아웃 메타데이터를 제공한다. appearance는 아직 구현되지 않았다고 명시한다.

## 완료 확인

- 고정 패턴, 0x80/0x01, 홀수 폭, 마지막 행을 복원해 content 픽셀이 입력과 일치.
- paper의 contentRect crop이 content와 정확히 같고 여백/이송 중복이 없음.
- PNG 압축 바이트의 OS 간 동일성 대신 디코딩 픽셀/치수를 비교.
- 실제 Linux .NET에서 생성 확인. SDK/네이티브 문제는 재현과 오류로 기록.

## 이번에 하지 않을 것

종이 질감·그림자 디자인, HTTP 작업 처리, 카메라, GDI, Windows 설치. 인공 패턴의 개발 검수 산출물과 실제 사용자 사진의 자동 저장을 혼동하지 않는다. 03 handoff 뒤 멈춘다.
