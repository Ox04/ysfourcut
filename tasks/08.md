# 08 — 네 장 촬영과 재촬영

- 권장 모델: **Opus 5 / medium**
- 입력: `08 진행해`
- OMC 입력: `/ys-task 08`
- 선행 작업: 07.
- 목표: 디자인된 화면에 실제 카메라 상태와 정확한 네 컷 촬영을 연결.

## 이번에 읽을 것

- 진행표, 07 handoff, `docs/UI_DESIGN.md`의 촬영 컴포넌트/상태 부분.
- `docs/PROJECT_RULES.md`의 촬영과 사진 처리 절.
- `SERVICE_DESIGN.md`의 4절, `WSL_DEVELOPMENT.md`의 1절.

## 할 일

1. Windows 브라우저 getUserMedia로 카메라 선택/준비/권한 거부/장치 분리를 처리한다. 웹캠을 WSL USB로 넘기지 않는다.
2. 준비된 영상 프레임만 캡처한다. 3초 카운트다운을 컷마다 반복하여 슬롯 네 개에 정확히 한 장씩 저장한다. 준비되지 않은 검은 프레임을 확정하지 않는다.
3. 촬영 취소, 전체 다시 찍기, 한 슬롯 재촬영을 구현한다. 개별 재촬영도 카운트다운을 거치고 다른 세 사진은 보존한다.
4. 미리보기와 캡처의 반전/크롭을 일치시키며 사진 비율을 늘리지 않는다. 프레임 글자까지 좌우 반전시키는 구조를 피한다.
5. 세션 ID/캡처 revision으로 늦은 타이머·비동기 프레임을 무효화한다. 연타, React effect 재실행, 화면 이동으로 중복 캡처되지 않게 한다.
6. 원본은 브라우저 메모리에만 두고 장치 변경/종료 때 track과 타이머를 정리한다. 09가 쓸 원본/슬롯 계약을 연결한다.

## Acceptance Criteria — 완료 확인

[공통 완료 기준](DEFINITION_OF_DONE.md)을 적용한다. 변경 범위는 카메라/촬영 상태와 07 UI의 연결부다.

| ID | 통과 조건·검증 |
| --- | --- |
| AC-08-01 | 준비된 영상에서 각 컷의 3초 카운트다운 후 정확히 네 슬롯이 채워진다. 연타/React effect 재실행으로 중복 슬롯이나 빈 프레임이 확정되지 않는다. |
| AC-08-02 | 한 슬롯 재촬영은 그 슬롯만 바꾸고 다른 세 원본은 보존한다. 취소/전체 재촬영 뒤 늦은 타이머·프레임이 이전 세션을 복원하지 않는 시험이 통과한다. |
| AC-08-03 | 권한 거부/장치 없음/장치 분리에서 한국어 오류와 가능한 복구 동작을 표시한다. 장치 변경·종료 뒤 이전 track·타이머가 정리된다. |
| AC-08-04 | 실제 Windows 브라우저·웹캠에서 촬영/반전/크롭/재촬영을 확인한다. 자동 가짜 카메라 시험과 분리하며 실물 웹캠 미확인은 NOT_RUN이다. |
| AC-08-05 | 07의 토큰/배치를 유지하고 원본 사진을 서버·로그·영구 저장소에 쓰지 않는다. 관련 자동 시험과 웹 typecheck/lint/build가 통과한다. |
