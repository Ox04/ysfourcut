# 99 — 막힌 작업의 원인 하나 해결

- 권장 모델: **Fable 5 / high**
- 입력: `99 진행해`
- OMC 입력: `/ys-task 99` — Fable 메인 세션에서 지정된 원인 하나만 조사한다.
- 실행 시점: 원인이 불명확한 실패가 반복되어 진행표에 대상 번호를 기록한 경우만.
- 목표: 기존 시도를 반복하지 않고 재현 가능한 원인 하나를 찾아 최소 수정.

## 먼저 읽을 것

진행표의 `99번에서 해결할 대상`과 그 번호의 task/handoff, 직접 관련된 코드/짧은 실패 로그만 읽는다. 대상이 없으면 번호를 추측해 전체 앱을 재검토하지 말고 현재 기록에서 차단 문제 존재 여부만 확인한다.

## 할 일

1. 재현 조건, 기대/실제 결과, 시도한 수정과 실패 이유를 확인한다. 원인 후보를 좁히는 작은 관찰/검사를 먼저 수행한다.
2. SDK 부재·권한·프린터 미준비·사용량 한도처럼 모델로 해결할 수 없는 조건이면 그 사실을 명확히 남긴다. 보호 장치를 우회하거나 유료 사용을 켜지 않는다.
3. 원인 하나와 직접 관련된 코드만 수정하고 회귀 검증한다. 리팩터링·디자인 교체·새 기능 추가로 범위를 키우지 않는다.
4. 원래 작업의 handoff에 원인/수정/검증과 남은 완료 조건을 적고 99 handoff에는 핵심 근거만 남긴다. 현재 문제를 해결했다고 원래 작업 전체를 자동 완료 처리하지 않는다.
5. 원래 번호의 권장 모델로 돌아갈 재개 문장 `NN 이어서 해`를 안내하고 멈춘다. 모델은 사용자가 선택한다.

## Acceptance Criteria — 완료 확인

[공통 완료 기준](DEFINITION_OF_DONE.md)을 적용한다. 변경 범위는 기록된 대상 문제의 직접 원인과 해당 검증이다.

| ID | 통과 조건·검증 |
| --- | --- |
| AC-99-01 | 대상 번호·기대/실제 결과·재현 조건·기존 실패 시도를 확인하고 원인 후보를 구분하는 새 증거를 얻는다. 전체 앱 재설계로 범위를 키우지 않는다. |
| AC-99-02 | 코드 원인이면 최소 수정 후 기존 재현과 관련 회귀가 통과한다. 외부 조건이 원인이면 그 조건과 확인 근거를 명시하며 코드 해결/검증 성공으로 표시하지 않는다. |
| AC-99-03 | 원인·수정/외부 조건·검증·원래 작업의 남은 AC를 handoff에 기록한다. 원래 작업 전체를 자동 완료하지 않고 해당 번호로 돌아갈 입력을 안내한다. |
