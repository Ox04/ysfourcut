# 06 — 실패·중복·재시작·사진 정리

- 권장 모델: **Opus 5 / high**
- 입력: `06 진행해`
- 선행 작업: 05.
- 목표: 출력 도중 실패하거나 사용자가 바뀌어도 잘못된 성공·중복·사진 노출이 없음.

## 이번에 읽을 것

- 진행표, 05 handoff와 Jobs/Artifacts/worker/관련 API 코드.
- `VIRTUAL_PRINTER_DESIGN.md`의 6~9절, `SERVICE_DESIGN.md`의 9~10절.

## 할 일

1. 다음 작업에 한 번만 적용되는 가상 오류 API를 구현한다. 지연 0.5~10초, 용지 없음/덮개 열림/오프라인, 시작 전 실패, N행 후 실패를 지원한다. physical에서는 거부한다.
2. 주입 지연은 렌더링의 10초 제한과 분리한다. worker timeout/중단/부모 재시작을 처리하고 늦은 결과의 게시를 무효화한다. 확정 종료 전 잠금을 풀지 않는다.
3. 부분 결과는 complete=false 진단 결과이며 rendered로 바꾸지 않는다. 자동 재실행·다른 어댑터 전환·새 UUID 자동 재접수를 하지 않는다.
4. 응답 유실 시 같은 UUID로 상태를 복구하고, 동시 요청/프로필 변경/세션 정리의 경합을 점검한다. 설정과 새 촬영 시작이 진행 중 작업을 바꾸지 못하게 한다.
5. TTL·최대 건수·세션/전역 바이트 상한을 타이머와 퇴거 정책으로 지킨다. 읽기로 만료를 연장하지 않는다. 정리/만료 뒤에는 오래된 GET이 이미지를 복원하지 않는다.
6. 다음 촬영의 clear는 진행 중이면 409다. 삭제 실패 시 화면 사진부터 없애되 삭제 성공 또는 새 host의 빈 캐시 확인 전 다음 사용자 세션을 시작하지 못할 계약을 정한다.
7. 재시작 뒤 메타데이터만 남은 결과는 unavailable로 표시한다. actual OS 큐·종이 확인을 virtual 오류 복구에 요구하지 않는다.

## 완료 확인

- 연타/동시 UUID, 같은 ID 다른 본문, 응답 유실, worker 중단, 재시작을 실제 호스트에서 재현.
- 정리와 늦은 완료가 경합해도 이전 이미지가 다시 게시되지 않음.
- 테스트에서는 조절 가능한 시계/실패 훅으로 TTL·메모리 제한을 검사하고 실행 시간을 낭비하는 긴 sleep을 피함.
- 사진/base64/인증값이 로그·wwwroot·작업 기록에 남지 않음.
