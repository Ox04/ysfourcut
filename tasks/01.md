# 01 — WSL 실행 뼈대

- 권장 모델: **Sonnet 5 / medium**
- 입력: `01 진행해`
- 선행 작업: 없음. 기존 코드가 생겼다면 먼저 확인하고 보존한다.
- 목표: WSL에서 웹과 Linux .NET 호스트를 함께 시작할 최소 실행 구조.

## 이번에 읽을 것

- `tasks/PROGRESS.md`, 있으면 `tasks/handoffs/01.md`.
- `WSL_DEVELOPMENT.md`의 2~5절. Windows publish 설명은 아직 읽지 않아도 된다.
- `SERVICE_DESIGN.md`의 11절과 실제 패키지/프로젝트 설정 파일.

## 할 일

1. Linux Node/npm/.NET, 현재 저장소를 확인하고 `docs/ENVIRONMENT.md`에 실제 상태를 짧게 기록한다. 앞서 Fedora 42/Node 25/Linux .NET 미발견이었으므로 현재 상태를 재확인한다.
2. 프로젝트용 Node 24 LTS와 Linux .NET 10을 준비할 수 있는 범위에서 진행한다. 사용자 범위 설치와 기존 설정을 우선하고, sudo/배포판 업그레이드/전역 기본값 변경은 자동 실행하지 않는다. 막혀도 작성 가능한 소스·설정은 준비하고 실행 미검증을 기록한다.
3. `apps/web`의 React/TypeScript/Vite, `apps/print-host/YsFourcut.Host.csproj`의 `net10.0`, 공통 `packages/imaging`의 최소 프로젝트 구조를 만든다. npm 한 개와 lockfile을 사용한다.
4. `npm run dev`가 WSL의 Vite 5173과 .NET 4317을 함께 실행하게 한다. `/api` 프록시, strict port, 종료 정리를 구현한다. API가 준비되지 않으면 전체 준비 완료로 표시하지 않는다.
5. 아직 인증 작업 전이므로 최소 비민감 health 응답 외에 사진/출력/파일 경로 API는 노출하지 않는다. 02번에서 health도 세션 정책에 맞춰 정리한다.
6. 기본 화면은 연결 확인용 단순 화면만 둔다. 브랜드 디자인/카메라/가상 출력 성공 화면은 만들지 않는다. 개발·빌드·타입 검사·린트·기본 테스트 명령을 실제 파일에 맞춰 준비한다.

## 만들 산출물

- 웹/.NET 프로젝트와 실행 스크립트, 패키지 고정, 최소 README 실행 안내.
- `docs/ENVIRONMENT.md`, `tasks/handoffs/01.md`, 진행표 갱신.

## 완료 확인

- WSL에서 실제 .NET 프로세스와 Vite가 뜨고 프록시로 health가 전달된다.
- 프로세스 종료 후 앱이 띄운 서버만 정리되고 다른 서버를 종료하지 않는다.
- Windows 루프백 접속 확인 여부와 빌드/명령 결과를 기록한다. SDK를 준비하지 못했으면 partial/blocked이며 실행 완료로 쓰지 않는다.

## 이번에 하지 않을 것

프린터 조사 반복, Skia 구현, 실제 사진 처리, 전체 UI, 계정/결제/클라우드, Windows 드라이버 설치. 02번으로 자동 진행하지 않는다.
