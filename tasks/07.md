# 07 — 포토부스 전체 UI 디자인

- 권장 모델: **Fable 5 / high**
- 입력: `07 진행해`
- OMC 입력: `/ys-task 07` — Fable 메인 세션에서 직접 디자인한다.
- 선행 작업: 04, 06. 렌더 결과와 상태 계약을 이용하되 기능 연결은 08~10에서 완성한다.
- 목표: 실제 React 컴포넌트로 촬영·편집·영수증 결과의 일관된 시각 디자인 완성.

## 이번에 읽을 것

- 진행표, 04/06 handoff, 웹의 현 상태, `docs/RECEIPT_APPEARANCE.md`와 실제 API 타입.
- `IMPLEMENTATION_OUTLINE.md`의 2절, `SERVICE_DESIGN.md`의 4절.
- `VIRTUAL_PRINTER_DESIGN.md`의 4~5절과 8절 중 표시 규칙.

## 할 일

1. 사진과 영수증이 중심인 한국어 키오스크 화면을 만든다. 시작/촬영/편집/가상 결과, 별도 장치·가상 오류 패널을 일관되게 디자인한다.
2. 종이색·검정·포인트색 하나를 기본으로 정하고 타이포그래피, 간격, 버튼, 포커스, 좁은 화면 규칙을 실제 CSS 토큰/컴포넌트로 만든다. 일반 관리자 대시보드 같은 카드 나열과 긴 소개 문구는 피한다.
3. 촬영 프리뷰/카운트다운/1~4컷 진행, 재촬영 썸네일, 밝기/대비/프레임 편집, 가상 프린터 상시 표시와 결과의 주요 동작을 명확히 배치한다.
4. 결과 화면은 04의 서버 appearance PNG를 크게 보여 주고 원본/정확한 용지/픽셀 확대/치수/저장 모드를 제공한다. CSS로 서버 영수증을 새로 만드는 방식은 쓰지 않는다.
5. 48px 이상 주요 터치 영역, 키보드·포커스, 읽기 쉬운 대비, reduced-motion을 고려한다. 배출 효과는 서버 완료를 속이는 신호가 아니라 표시 애니메이션이다.
6. API·카메라·편집 로직은 props/hooks 경계로 남겨 후속 구현이 디자인을 유지하게 한다. 미연결 기능은 명시하고, 개발 전용 상태 미리보기용 fixture를 제품의 출력 성공으로 사용하지 않는다.
7. 실제 브라우저에서 넓은 화면과 좁은 화면, 로딩/오류/긴 문구 상태를 본다. 디자인 방향 하나를 완성한다. 이미 정한 방향을 여러 대안으로 계속 재생성하지 않는다.
8. `docs/UI_DESIGN.md`에 토큰·컴포넌트·상태·후속 연결 위치를 간결하게 남긴다. 후속 모델은 이를 임의 재디자인하지 않는다.

## Acceptance Criteria — 완료 확인

[공통 완료 기준](DEFINITION_OF_DONE.md)에 따라 각 ID의 근거를 handoff에 기록한다. 변경 범위는 웹 UI와 `docs/UI_DESIGN.md`이며 API·렌더 계약을 재작성하지 않는다.

| ID | 통과 조건·검증 |
| --- | --- |
| AC-07-01 | 시작/촬영/편집/결과와 장치·오류 패널이 실제 React/CSS로 렌더링되고 주요 동작·가상 상태가 식별된다. 실제 브라우저에서 각 상태를 본다. |
| AC-07-02 | 04/05의 실제 서버 appearance PNG를 결과 뷰어에 표시하고 content/paper/픽셀 확대/치수 모드가 콘텐츠를 왜곡하지 않는다. CSS로 영수증 원본을 다시 만들지 않는다. |
| AC-07-03 | 1280×800과 390×844에서 긴 한국어 문구·세로 영수증·로딩/오류를 확인하고 의도하지 않은 잘림/겹침이 없다. 주요 터치 영역은 48px 이상이다. |
| AC-07-04 | 키보드로 주요 동작에 접근하고 포커스가 보이며 reduced-motion에서 불필요한 배출/전환 효과가 줄어든다. 서버 완료 전 성공 표현이 없다. |
| AC-07-05 | 토큰·컴포넌트·props/hooks 연결 위치를 UI_DESIGN에 기록하고 실제 연결/미연결/개발 fixture를 구분한다. 관련 typecheck/lint/build가 통과한다. |

## 이번에 하지 않을 것

카메라/디더링 알고리즘 구현, API 계약 재설계, 회원가입·결제·갤러리, 외부 자산/브랜드 복제. 07 handoff를 저장하고 멈춘다.
