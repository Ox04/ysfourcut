# 02 — API 계약·프로필·로컬 인증

- 권장 모델: **Opus 5 / high**
- 입력: `02 진행해`
- 선행 작업: 01.
- 목표: 뒤의 작업들이 그대로 쓸 타입과 인증 경계를 실제 코드로 고정.

## 이번에 읽을 것

- 진행표, 01 handoff, 있으면 02 handoff와 기존 API/설정 코드.
- `SERVICE_DESIGN.md`의 8절·10절.
- `VIRTUAL_PRINTER_DESIGN.md`의 3절·5절·7절, `WSL_DEVELOPMENT.md`의 4절.

## 할 일

1. TS/C# 요청·응답 타입과 오류 코드를 맞춘다. `schemaVersion=1`, UUID, profile ID/revision, bitmap width/height/stride/MSB-first/blackBit/base64 계약을 고정한다.
2. 1MiB 본문, 최대 1024×4096dot/해제된 512KiB, 정확한 stride와 데이터 길이, 흰 padding을 검사한다. 프로필 상한을 추가 적용하고 JSON/base64 오류를 구조화한다.
3. `kind=virtual/hardware`, 서버의 `virtual/physical` 모드를 분리한다. virtual 80/58mm 프리셋을 넣고 actual AHAPOS 검증으로 표시하지 않는다. Linux의 physical은 거부한다.
4. 루프백 Host, 정확한 Origin, JSON/전용 헤더, 세션 쿠키, 일회용 bootstrap을 구현한다. Vite 프록시를 지나도 보안 검사를 유지한다. 브라우저로 bootstrap 정보를 전달할 방법과 만료/재사용 거부를 실제로 연결한다.
5. health/printers/profile API를 인증 정책에 맞춰 제공한다. virtual에서 Windows 프린터 열거를 호출하지 않는다. 프로필 revision 변경은 후속 작업의 스냅샷과 일치하도록 설계한다.
6. 출력/이미지 API는 타입만 선언하고 05번 전에는 명확한 미구현/미제공 상태로 둔다. 사진을 받았다며 가짜 성공을 반환하지 않는다.
7. `docs/API_CONTRACT.md`에 실제 타입/경로/오류와 담당 코드 위치를 간결하게 남긴다. 긴 별도 전체 설계서를 다시 쓰지 않는다.

## 완료 확인

- 정상 세션/프로필 조회, 잘못된 인증·Origin·Host·크기·padding·revision 거부를 의미 있는 테스트로 확인.
- 쿠키·코드·사진이 로그/오류 응답에 포함되지 않음. 개발 화면에서 인증 성공.
- 타입/endpoint 구현 여부가 명확하여 뒤의 작업이 추측할 필요 없음.

## 이번에 하지 않을 것

렌더러, 작업 큐/worker, 카메라, 전체 UI, 실제 인쇄. 끝나면 02 handoff와 진행표를 저장하고 멈춘다.
