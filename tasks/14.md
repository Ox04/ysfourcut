# 14 — 실행·복구 문서와 납품 기록

- 권장 모델: **Sonnet 5 / low**
- 입력: `14 진행해`
- OMC 입력: `/ys-task 14`
- 선행 작업: 11~13의 구현/검수 기록. partial 항목은 있는 그대로 보존한다.
- 목표: 사용자가 문서만 보고 가상 앱을 실행하고 문제를 복구할 수 있음.

## 이번에 읽을 것

- 진행표, 11/12/13 handoff, 실제 README/스크립트/프로젝트 설정.
- `docs/ENVIRONMENT.md`, `docs/VALIDATION.md`의 결과/미확인 항목.
- `WSL_DEVELOPMENT.md`의 실행 명령, `docs/PRINTER_REFERENCE.md`의 미확인 항목.

## 할 일

1. README를 실제 존재하는 명령과 파일 기준으로 정리한다. WSL 개발 실행, Windows 브라우저/웹캠, 가상 80/58mm, PNG 저장/삭제, 오류 시험을 설명한다.
2. Windows 배포 폴더 실행과 개발 실행을 구분하고 개발 SDK가 필요한 쪽을 명확히 한다. 설계상의 미래 명령을 이미 작동하는 명령처럼 쓰지 않는다.
3. 서버 미실행·권한 거부·포트 충돌·만료·삭제 실패·가상 오류의 복구 방법을 짧게 쓴다. 보안 검사 해제나 전체 큐 삭제를 해결책으로 넣지 않는다.
4. `docs/HARDWARE_CHECKLIST.md`에 후속 AHAPOS 준비/모델/폭/드라이버/작은 패턴/연속 인쇄 검수 항목을 적는다. 아직 확인하지 않은 체크를 채우지 않는다.
5. WSL 가상 검수, Windows 가상 검수, 디자인 마감, AHAPOS 실물 검수의 결과를 분리한다. 미완료 작업을 진행표에서 done으로 바꾸지 않는다.
6. 문서 링크와 경로·명령을 실제 파일과 대조한다. 문서 정리 때문에 전체 테스트나 UI 재생성을 반복하지 않는다.

## Acceptance Criteria — 완료 확인

[공통 완료 기준](DEFINITION_OF_DONE.md)을 적용한다. 변경 범위는 README·납품/하드웨어 체크리스트·문서 링크다. 문서 정리 때문에 앱을 재구현하거나 전체 검증을 반복하지 않는다.

| ID | 통과 조건·검증 |
| --- | --- |
| AC-14-01 | WSL 개발 실행과 Windows 배포 실행의 명령/경로/필요 런타임이 실제 산출물과 맞는다. 존재하지 않는 명령이나 미래 기능을 현재 기능으로 설명하지 않는다. |
| AC-14-02 | 가상 80/58mm·PNG 저장/삭제·오류 시험과 서버 미실행/권한 거부/포트 충돌/만료/삭제 실패의 복구 절차가 있다. 보안 해제·전체 큐 삭제를 요구하지 않는다. |
| AC-14-03 | WSL 가상/Windows 가상/실제 웹캠/디자인/AHAPOS 검수 상태를 분리하고 11~13의 NOT_RUN·partial을 보존한다. 하드웨어 체크리스트는 실제 확인한 항목만 완료로 표시한다. |
| AC-14-04 | 수정한 문서의 링크·명령·경로를 대조하고 OMC 진입점/짧은 번호형 요청을 유지한다. 전체 설계서를 한 번에 입력하라고 안내하지 않는다. |
