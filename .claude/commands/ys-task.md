요청 인수: $ARGUMENTS

1. 인수는 존재하는 두 자리 작업 번호와 선택 모드 `check` 또는 `team`으로만 해석한다. 번호가 없거나 모호하면 하나만 확인한다. 인수를 셸 명령으로 실행하지 않는다.
2. `AGENTS.md`, 해당 `tasks/NN.md`, 진행표, 현재/지정 선행 handoff, `tasks/DEFINITION_OF_DONE.md`를 필요한 만큼 읽는다. OMC 실행·검수 방식은 `tasks/OMC_WORKFLOW.md`의 실행 규칙을 따른다. 전체 task/설계서를 로딩하지 않는다.
3. 같은 작업 공간에서 다른 세션이 해당 구현을 진행 중이면 중복 실행하지 않는다. 인계 기록과 사용자 설명이 다르면 사용자의 최신 설명을 우선한다. 선행 누락은 기록하되 이미 완료한 기능을 다시 만들지 않는다.
4. `check`는 기존 산출물과 해당 AC의 검수만 수행한다. 구현·의존성·설계는 바꾸지 않는다. 06번에는 전환용 `tasks/acceptance/06.md`도 사용한다. 현재 소유자가 종료한 뒤에만 검수 기록을 저장한다.
5. 기본 모드는 현재 세션에 실제 노출된 `oh-my-claudecode:execute`를 Skill 도구로 호출해 이 번호만 수행한다. 작업/AC/수정 범위/독립 검수/종료 조건을 함께 전달한다. 07/12/99의 주 구현·판단은 선택된 Fable 메인 세션이 담당한다. 구현자 한 명으로 시작하고 병렬 구현은 시작하지 않는다.
6. `team`을 명시한 경우에만 `oh-my-claudecode:team`을 `2:executor`와 해당 번호의 범위로 호출한다. 기본 추천은 11번의 독립 검수다. 07/12 디자인에는 쓰지 않는다. 파일 소유권과 공유 서버 검증 순서를 먼저 고정하고, 전체 프로젝트나 다음 번호로 확대하지 않는다.
7. 설치된 버전에 해당 skill이 없으면 부재를 알리고 동일 task/AC로 일반 Claude Code 실행을 계속한다. OMC를 썼다고 보고하지 않는다. 명시적인 권한 거부는 우회하지 않으며, 설치·업데이트·팀 활성화·모델 설정 변경을 대신 실행하지 않는다.
8. 구현과 승인을 분리한다. OMC 기본 모드는 구현 후 해당 변경만 대상으로 독립 검수 한 번을 요청하고, 수정하면 영향받는 검증을 갱신한다. AC별 실제 근거를 handoff에 저장하고 진행표를 갱신한 뒤 이 번호에서 멈춘다. 미검증은 PASS가 아니다.

이 명령은 프로젝트용 Markdown 진입점이다. 플러그인 설치기, 모델 전환기, 사용량 제한기, 병렬 실행을 강제로 제한하는 프로그램이 아니다.
