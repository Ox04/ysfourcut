요청 범위: $ARGUMENTS

## 권한과 목적

이 명령을 사용자가 직접 호출한 것은 지정 범위의 번호를 **순차적으로** 구현·검수하고, 통과하면 다음 번호를 시작하라는 요청이다. 배포·결제·외부 API/모델·커밋·푸시·실물 인쇄·드라이버/전역 설정 변경 권한은 포함하지 않는다.

이 명령이 해당 세션의 유일한 연속 실행 관리자다. 같은 세션에서 Autopilot, Ralph, Team, Graph, `/goal` 같은 다른 지속 루프를 함께 시작하지 않는다. 작업자는 동시에 한 명만 사용하고 공유 파일·서버 검증을 병렬화하지 않는다.

## 범위 해석

1. 인수는 시작/끝 두 자리 번호로만 해석한다. 기본 시작은 `tasks/PROGRESS.md`에서 08~14 중 첫 pending이며 기본 끝은 14다. 시작만 있으면 그 번호부터 14까지다. 역순, 존재하지 않는 번호, 90/91/99 포함은 거부한다. 인수를 셸 명령으로 실행하지 않는다.
2. 현재 권장 실행은 `/ys-series 08 14`다. 이미 끝난 범위 안의 번호는 handoff와 진행표를 확인하고 건너뛴다. `partial`은 필요한 구현/계약이 존재하고 미확인 사유가 다음 작업을 막지 않을 때만 넘어갈 수 있다. `blocked`, AC FAIL, 필요한 산출물 부재에서는 멈춘다.
3. 다른 세션이 범위 안의 번호를 진행 중이라는 최신 사용자 설명이나 in_progress 기록이 있으면 중복 시작하지 않는다. 기존 프로세스와 서버를 자기 소유로 간주하지 않는다.

## 번호별 모델

각 구현 작업자를 호출할 때 모델을 명시한다. 사용자 세션의 `/model` 설정을 바꾸거나 기본 OMC 라우팅에 맡기지 않는다.

| 번호 | 구현 모델 | 검수 모델 |
| --- | --- | --- |
| 08 | opus | sonnet |
| 09 | opus | opus |
| 10 | opus | opus |
| 11 | opus | opus |
| 12 | fable | sonnet |

Fable은 12번의 시각 판단과 직접 수정에 사용한다. Sonnet 검수자는 디자인을 새로 만들지 않고 AC·접근성·회귀만 확인한다. agent 호출에서 `fable` 별칭을 지원하지 않으면 다른 모델로 대체하지 말고 12번 직전에 멈춰 실제 지원 모델을 보고한다. effort는 이 명령이 자동 변경했다고 주장하지 않으며 실제 확인 가능한 값만 handoff에 쓴다.

## 각 번호의 순차 루프

각 번호마다 다음 순서를 끝낸 후에만 다음 번호로 이동한다.

1. 메인 관리자는 `AGENTS.md`, 현재 `tasks/NN.md`, `tasks/PROGRESS.md`, 지정 선행 handoff, `tasks/DEFINITION_OF_DONE.md`의 필요한 부분만 읽는다. 전체 task/설계서/로그를 한꺼번에 읽지 않는다.
2. 현재 Claude Code에 실제 노출된 `oh-my-claudecode:executor` 작업자를 위 모델로 **한 명** 호출한다. 작업자에게 현재 task/AC/읽을 파일/금지 범위, 기존 코드 보존, 실제 검증, handoff·진행표 갱신, 다음 번호 금지를 전달한다. 하위 작업자나 Team을 다시 만들지 말라고 명시한다.
3. 작업자가 끝나면 메인 관리자가 실제 변경 파일, handoff의 모든 AC 행, 진행표, 관련 검증 결과를 확인한다. 작업자의 완료 문장만으로 통과시키지 않는다.
4. 다른 OMC `verifier` 또는 읽기 전용 검수자를 표의 검수 모델로 한 명 호출한다. 현재 번호의 변경과 관련 코드만 보게 하고 AC별 PASS/FAIL/NOT_RUN, 회귀·보안/개인정보·범위 위반을 판정하게 한다. 검수자는 코드와 진행표를 수정하지 않는다.
5. 필수 결함이 있으면 같은 번호/구현 모델의 수정 작업자 한 명에게 **구체적인 검수 결과만** 전달한다. 수정 후 영향받은 검증과 독립 검수를 다시 수행한다. 같은 원인에 대한 수정은 최대 두 번이며, 그 뒤에는 재현·시도·근거를 저장하고 99번 대상으로 표시한 후 시리즈를 중단한다.
6. 다음 번호로 갈 수 있는 조건은 모두 충족해야 한다.
   - 해당 번호 handoff가 존재하며 모든 AC에 결과와 실제 근거가 있다.
   - 필수 AC에 FAIL이 없고 자동 검증/화면/환경 범위가 정직하게 기록됐다.
   - 진행표 상태가 `done`, 또는 다음 선행 계약을 충족하면서 환경 확인만 남은 `partial`이다.
   - 독립 검수에서 필수 결함이 없고 수정 후 근거가 최신이다.
   - 실행 중으로 남긴 자기 소유 서버가 있으면 다음 작업과 충돌하지 않도록 handoff에 소유/종료 방법이 있다.
7. 조건을 만족하면 다음 번호를 시작한다. 번호 사이에 사용자 확인을 요구하지 않는다. 다음 번호의 task가 사용자 입력·실제 웹캠·Windows UI 등 현재 수행할 수 없는 필수 조건을 요구하면 가능한 자동 작업과 기록을 먼저 마친 뒤 `partial`/`blocked`로 멈춘다. 성공을 추측해서 건너뛰지 않는다.

## 재개와 종료

- 컨텍스트가 부족해지면 현재 번호 handoff와 진행표를 먼저 저장한다. 새 작업을 어중간하게 시작해 놓고 종료하지 않는다.
- 세션/사용량 제한/도구 중단 후 사용자가 같은 `/ys-series START END`를 다시 실행하면 범위의 handoff·진행표를 대조해 첫 미완료 번호부터 재개한다. OMC 내부 상태만 보고 완료를 추측하지 않는다.
- 사용자가 `stop`, `cancel`, `중지`라고 하면 현재 안전한 지점에서 자기 작업자만 중단하고 현재 번호를 기록한 뒤 종료한다.
- 끝 번호까지 통과하면 변경 요약, 번호별 최종 상태, 검증/미확인 환경, 사용 모델, 남은 90/91을 한 번만 보고한다. 90/91/99는 자동 실행하지 않는다.

OMC executor/verifier 또는 명시 모델 호출이 현재 설치에서 제공되지 않으면 일반 단일 세션으로 전체 시리즈를 흉내 내지 않는다. 시작 전에 부재와 필요한 `/omc-setup` 또는 버전 확인을 보고하고 멈춘다.
